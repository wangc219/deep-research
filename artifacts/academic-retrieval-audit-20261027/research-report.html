二、源码中限制广度与深度的地方

  1. 主题查询都进入 keyword 字段。 AcademicRetrievalService 将 topic 查询发送到 /paper/search/pro 的 keyword 字段。AMiner 接口资料将其描述为字段字面匹配，而 QA 类接口用于自然语言查询。应区分精确术语、标题短语、摘要条件和语义问题；不能用同一查询方式覆盖所有任务。中性对照说明 keyword 不是普遍不可用，不能声称“换成 title 就一定解决”。AMiner 接口参考
  2. 缺少任务相关性重排。 多个查询的候选交错合并、去重，再截断到 limit；这并不等于按当前问题的论证需要重新排序。默认候选 10 条，最多 20 条；多角度结果也共享最终数量限制。需要更大的内部候选池，但只把少量高相关证据交给写作模型。
  3. 已有“深度”主要是摘要和一层参考文献。 当前工具没有统一的全文证据读取、页面/段落定位、后续引用者与相似论文发现链路。完整摘要仍不足以支持实验细节、外推性能和应用级可行性。
  4. 引用依赖模型逐字抄 URL。 搜索跳转地址长且脆弱，模型改协议、漏字符或拼入记忆中的新闻网址都会失败。应由服务端分配 source_id 并渲染引用；只有真实抓取或可靠标识核验过的地址才登记为别名。
  5. 来源真实性与论断支持度尚未分开。 目前检查主要是“地址来自本轮工具”和“是否尝试取摘要”，并不能证明某篇论文的内容支持具体句子。需要独立的 claim→evidence 段落映射和证据级别。

四、对当前项目的推荐顺序

P0：先让现有链路可靠。 分别处理精确术语、短语、语义问题；同一接口连续空结果后切换字段/来源，不继续机械堆同义词。工具结果由可信适配层登记 source_id、DOI/原始标识、实际取得的 URL、证据级别与时间；父子任务共享同一用户研究轮次的登记表。模型引用 source_id，由服务端渲染 URL，保留来源真实性检查。失败时交付已核实部分并明确缺口，不把未完成的子任务包装成完整证据。

P1：补广度和文献关系。 保留 AMiner，增加 OpenAlex 与 Semantic Scholar；统一 DOI 去重，融合候选并按问题相关性重排，同时保留新论文和经典论文的位置。围绕少量相关种子，按需查参考文献、后续引用与相关推荐。以“新增有效证据是否还在增加”决定继续或停止，不设机械凑数要求。

P2：补全文深度。 从公开出版页、开放获取仓库或用户已获授权文档取得原文，复用知识库解析与缓存；只读取支持关键论断的段落、图表和实验条件。把“题录、摘要、原文直接证据、类比推断、待验证假设”分开展示。Crossref 负责身份/状态核验，原文证据决定论断支持程度，两者不能互相替代。

问题拆分 → 按接口语义选择查询
        → 多源候选 → DOI去重与任务相关性重排
        → 种子论文关系扩展 → 原文/段落证据读取
        → claim–evidence核验 → source_id引用渲染
        → 有据结论 + 尚未解决的证据缺口

对缺乏直接权威证据的前沿主题，应标明“本轮没有取得足够的直接证据”，区分基础研究与应用外推。不能用相关论文数量、期刊名或引用次数替代直接支持，也不能把检索为空写成“不存在”。

五、验收方式与资源约束

下一阶段建议用 20–30 个公开通用科研问题与已知相关 DOI 做盲评，覆盖常见主题、长尾术语、多词歧义、相互矛盾证据和确实无证据的问题。与当前版本对照：相关论文召回、前 10 条相关率、原文可取得率、关键论断的直接证据支持率、错误引用率、父子来源传递、P95 时间与费用。缺证据问题应能正确保留缺口；来源真实不等于答案质量合格。这里只提出验收指标，没有声称新候选已取得某个提升百分比。

4 核 16 GB 下优先做轻量 API 聚合、共享缓存和现有 Worker 调度，不为每个用户复制一套全文解析或重排模型。文档解析先用现有资源调度控制并发，外部请求做限流与去重；具体并发值需经过多用户压测后确定。不会因为资料不足就盲目增大搜索次数或 CPU 并发。
