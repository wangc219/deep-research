发现与修复

首次 16 人真实模型测试出现 4 个失败：运行清单与资源解析持有只读连接，再嵌套申请同一个连接池。修复事务边界后，20 个普通对话加 1 个深研短对话全部完成。

提额测试发现默认智能体的知识库选项也会嵌套申请连接，造成约 30 秒等待。现已复用调用方 Session，保留权限过滤。真实 PostgreSQL 单连接测试确认既能完成查询，又不能读取其他用户的私有知识库。

最终验证

16 个普通账户通过生产 HTTPS 登录，20 个普通对话与 5 个新版深研短对话全部完成。模型计量表确认 25 次真实调用成功。单用户额外提交多条聊天及 3 个深研请求，排队后均完成，负载期间页面探测全部成功。

本地相关回归 255 项通过；云端候选镜像 7 项通过，其中包含两个真实 PostgreSQL 场景。分池上线后的父子任务 E2E 验证真实模型、文件共享、流式输出和两个不同 Worker 的执行记录；该 E2E 在最后的资源查询优化前完成。

资源采样 100 秒，CPU 短时峰值 100%，Swap 为 0。最终 API 与四个 Worker 健康、无 OOM、同一镜像；最终修复上线后的 API 日志无 5xx。CPU 相对权重优先保障 API 与普通聊天，剩余内存可用于识别、索引、大文件及文件缓存。
