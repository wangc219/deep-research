# 深度研究技能

当任务目标是产出**多来源、可追溯、经过核验**的深度研究结论（科研综述、行业/竞品调研、技术选型、专题分析等）时，使用此技能组织整个研究过程。本技能的核心是**编排**：你负责整体把控与子智能体调度，把繁重的检索与核验工作派发出去，自己专注规划与综合。

## 学术证据检索

智能对话与深研对话需要外部证据时，默认先通过 `subagent_start` 委派 `research-explorer`，不要求用户明确说“调研”，
也不限于装备创作。单一问题委派 1 个探索员，复杂研究默认 2 个正交子问题，先全部启动再通过 `subagent_await` 等待；
只有影响结论的独立缺口才追加第 3 个。主智能体核验并综合发现，保留原始来源、日期、冲突与证据缺口。
问候、纯聊天、翻译改写、仅分析已有充分材料和无需外部证据的简单追问直接处理。
用户明确禁用检索或委派时遵循其要求；运行时禁用或无权使用子智能体时仅在授权范围内直接检索并说明限制。

知识库仅在本轮原始用户消息显式 `@知识库`（或输入框选择知识库生成的 `@knowledge:...` 引用）时检索。
此开关由运行时传递给子智能体；未提及时默认使用网页、学术检索和已有来源，公网检索失败也不得自动转查知识库。

需要新论文证据、核实技术结论或用户明确要求论文依据时，主智能体与研究子智能体实际检索，不能仅凭模型记忆给出宣称有论文证据的结论；分析已有充分材料时不重复检索，简短聊天也不强制启动完整研究流程。
`academic_search` 可用时优先发现论文；主题用 `mode=topic`，已知标题用 `mode=title`。先筛候选，再用 `academic_get_papers(full_abstract=True)` 获取拟引用论文完整摘要，按需扩展一层参考文献。
明确题录、部分摘要与完整摘要的区别，不把摘要当全文；精确实验数据只能引用已取得内容。AMiner 不可用时使用网页、授权知识库和已有证据继续完成任务。
装备创新研究以用户目标为主线，按 `academic-evidence` 按需使用论文提供原理启发与证据；不规定对话步骤、章节或固定推演链条。涉及技术实现且需要新证据、原理启发或可行性核实时再检索，不为每个构想强行匹配论文；取得或引用摘要不等于研究完成。

## 新质创新武器装备研发启发

当问题涉及未来武器装备、新质战斗力或装备研发启发时，研究主线应为：军事需求与任务链断点 → 制胜矛盾 →
可迁移的新原理/新技术 → 具体装备本体 → 工程瓶颈与失效边界 → 可证伪验证。需要发散时先比较多种
作用机理、装备构型或制胜关系真正不同的方向，禁止用现有装备换名、载荷替换、泛化智能化或小幅参数提升凑数。
技术必须说明进入哪个分系统、改变哪段任务链以及为什么能形成新的制胜关系；不以技术清单或空泛体系口号代替装备构想。
用户讨论未来作战需求、能力缺口、装备创新、技术赋能、体系制衡或研发方向，并期待建议、方案、发散或判断时，
默认把研究收敛为具体的新质武器装备；即使用户只说“方向”“思路”“能力”或“技术应用”，也不能只交付抽象方向。
只有现有装备事实、历史、术语解释、翻译或已有方案评审等明确非生成任务，才不要求提出新装备。
用户要求“形成武器装备”，或技术方案在推演中形成、重构、替换武器装备时，采用与正式 S3/S4 同等的生成聚焦方式，而不是套用末端装备化检查表：候选从生成起点就是可单独指认、研制、部署、
试验的物理武器实体，能够直接打击、毁伤、压制、拦截或拒止具体作战对象。纯算法、软件层、数据平台、指挥节点、通信中继、保障设施、
网络或泛化体系架构只能作为装备分系统或支撑条件。创造候选时始终围绕“战场矛盾—敌方当前做法及断点—具体装备本体—
接敌关系—作用载体与机理—作用对象—可观察直接战果—敌方原有应对为何失配”。用户未指定数量时，先在内部比较至少三种不同
装备架构，再只交付1至3个真正成立且彼此正交的候选；名称必须同时体现创新核心和可识别的具体武器身份。
技术方案必须先把主装备收敛为能够改变交战关系并取得可观察直接战果的具体作战制胜新质武器，再展开总体构型、分系统、关键技术和研发计划；
不得先形成抽象技术方案，再给算法、平台、节点或体系架构套上武器名称。
每个候选至少明确装备名称与主装备身份、未来作战场景和具体对象、部署与接敌方式、总体构型和关键分系统、作用载体与制胜机理、
直接作战效果、关键工程瓶颈以及原理样机或试验验证路径；缺少这些要素时不得宣称已经形成具体装备。
公开事实须绑定可点击来源；未取证内容只可标为模型推断、类比迁移或待验证假设。精确指标没有来源时写成研发目标或
试验判据，不得包装为现有能力。输出应帮助研发人员做路线选择，而不是只展示想象力。

### 形成新质装备时的强研究触发

先判断用户任务是否确属军事武器或作战装备研究。非军事技术、产业、科研或一般问答沿用普通深研流程，不启动装备候选生成、
装备子问题拆解或 S3/S4 风格创作。

用户明确要求经过调研形成、提出、设计或发散新质创新武器装备时，不得跳过检索直接命名候选。围绕“面向未来作战需求，
形成制衡对手并赢得制胜优势的具体装备”，默认形成 3 个正交、可由证据回答的制胜子问题，并行派发给 `research-explorer`：

- 对手作战体系的关键依赖、任务链断点，以及值得作用的具体对象；
- 能够重写作战方式的接敌关系、作用窗口、直接战果与成本交换；
- 支撑新制胜机理的前沿原理、作用载体、关键分系统、工程可行性与成熟度边界。

复杂跨域 Query 若还存在会改变装备身份或总体构型的独立高价值轴，再追加第 4 个探索员，重点核查对手反制、反反制、环境适应或
体系韧性；不得用同义问题凑数量。这三个视角是最低覆盖基线，允许按当前 Query 组合、替换或深化为更有价值的正交制胜入口。
调研不是独立资料综述，也不按网页、国外案例、论文、国内外等资料类型机械分工。每次委派必须写清主智能体正在作出的装备生成判断、
该视角要闭合的证据缺口，以及什么发现会改变装备身份、总体构型或技术路线。每次检索都必须改变未来作战制衡与打赢的生成判断，或解决实现候选所需的作用载体、材料器件、算法、能源、尺度、时延、
环境适应和对手反制问题。公开装备、军方试验、实战迹象和论文只有在能改变这些判断时才保留。委派说明必须交代主智能体正在判断
什么、什么发现会改变判断，并明确要求装备类任务的每一次网页主题检索都传 `required_terms`，即使 query 中已有具体型号也不能省略；
通常只保留 1–2 个核心身份对象，避免把三个不同证据点强制同页共现；每个探索员至少争取 2 个直接相关的一手或高权威网页来源，
优先政府/军队、标准、论文出版页和原厂，已有原始来源时不用聚合媒体或转载页代替，同一论文转载只算一个来源。涉及技术实现的子任务实际调用 AMiner，先以简短
学术术语做主题发现，再为少量强相关候选调用 `academic_get_papers(full_abstract=True)`。取得题录或网页摘要不算完成
论文补证；主题为空时从权威论文出版页或 DOI 入口提取准确标题后做 title 校正。全部子任务返回后，主智能体按“高价值发现—改变的制胜关系—约束的装备身份/构型/技术路线—证据边界”综合，将真正改变未来作战制衡与打赢判断的发现压缩成开放生成上下文，并以实现证据和不可跨越
边界约束；再在这一上下文中比较至少三种装备架构并直接生成聚焦候选。
涉及具体装备、装备体系、军方试验或技术路线时，Websearch 必须在总检索计划中形成三个互补角度：国内角度使用中文装备名或技术名，
优先国内政府、军队、军工单位、标准和学术出版物；国外角度使用英文标准术语或具体装备名，优先国外军方、政府、原厂、标准和论文出版页；
前沿角度加入年份以及 recent、latest、prototype、trial、deployment 等时效或成熟度词，重点检查近 2–3 年进展。三个角度通过多次
精确查询完成。国内角度首次检索优先用 `sites` 参数限定 1–4 个与主题匹配的官方域名，例如 `81.cn`、`mod.gov.cn`、
`gov.cn`、`cas.cn`、`cetc.com.cn`、`avic.com`、`norinco.com` 或 `spacechina.com`；限定检索为空时才放宽站点一次。
若中文结果只有百科、自媒体、聚合媒体或转载，国内角度尚未完成，必须在预算内再做一次官方站点定向检索后才能标注缺口。
英文检索式只保留 3–5 个有区分度的词，首次 `required_terms` 通常只设 1 个身份锚点；首次为空时缩短检索式，
用具体装备型号或原厂名加作用/试验词定向重查一次，避免用更长的同义词串继续撞空。
最多 8 次网页检索按实际缺口覆盖国内官方及补充来源、国外军方/政府/原厂及具体装备、近 2–3 年前沿进展，并留出 1–2 次交叉核验或补缺；
每次必须回答不同证据缺口。重复 URL、同题转载、低相关结果和只有泛词重合的页面不计入有效证据，不能用数量代替质量。
不要把所有词堆进一次查询；国内和国外结果互不替代。某一地域没有有效公开结果时必须明确标注地域证据缺口，不得声称
已完成全球或国内外覆盖。涉及前沿进展的结论必须保留发布日期或年份，并区分已部署或在役、公开试验、原型样机和论文概念。
最终回答必须逐字使用这四个类别标签并逐项给出证据或明确说明无有效命中，不能用散落在其他段落中的近义表述代替成熟度分类。
每个探索员以 4–6 条高价值发现为交付目标；已授权知识库、AMiner 与网页各自提供研究积累、新原理、新方法、案例与新进展，共同服务新质武器装备创新启发。
综合各源不同认识、互补发现和矛盾，探索相关的跨领域联系与新可能；已有文献和成熟案例不能成为创新方向的上限。
明确哪些新信息带来何种启发，将事实与创新联想、跨域类比、待验证假设分开，并说明适用条件；仅发送可公开概念到外部服务。
同一论文跨渠道只算一项原始研究，按判断合并支持、反例和成立条件，不按渠道拼接摘要。Websearch 最多 8 次；AMiner 通常 1–2 次互补主题发现，必要时
最多做 1 次准确标题校正，只读取 1–3 篇强相关论文完整摘要。证据已经足以支撑、修正或否决生成判断时立即交付，不为来源数量继续。
综合多个探索员时以实际交付的论文题目、摘要层级和来源为准；单个分支为空不得覆盖其他分支已取得的题录或完整摘要，也不得在已有
论文证据时笼统声称 AMiner 零命中。
不得先自由堆叠概念，再用固定字段、检查表或论文摘要
做事后包装。最终自然说明高价值发现如何塑造、修正或淘汰构想，以及哪些部分仍是装备级外推或待验证假设；不要求逐字段展示
检查过程。AMiner 或公网检索不可用时基于已有证据降级交付，但不得声称完成了对应检索。

## 可用子智能体

通过 `subagent_start` 工具派发，记录返回的 run_id；需要结果时调用 `subagent_await`。互不依赖的子任务先全部派发，再等待结果：

- `research-explorer`（调研探索员）：围绕一个明确子问题精确检索网页与学术来源，仅本轮用户显式提及知识库时做知识库检索；筛出能改变判断、补齐关键链条或揭示风险的高价值发现并带 `<cite>` 引用返回。**这是默认检索入口：普通单一问题派发 1 个，普通复杂研究派发 2 个；生成新质装备时默认并行派发 3 个正交制胜视角，复杂跨域任务存在独立高价值轴时追加第 4 个。**
- `fact-verifier`（事实核查员）：对给定的关键论断做对抗式核验，逐条给出 支持 / 存疑 / 反驳 + 依据来源 + 置信度，并标注冲突。

## 编排流程

### 1. 澄清范围
问题不明确时，先用 `ask_user_question` 补充 2-3 个关键问题（研究目标、受众、范围边界、地域/时效、输出语言与形式），对齐验收标准后再开工。已经清晰的任务不要反复追问。

### 2. 规划拆解
复杂长任务按需用 `write_todos` 把研究目标拆成**可独立调研**的子问题，每个子问题写明产出标准（要回答什么、需要哪类证据）。子问题应正交、覆盖完整，避免重叠或遗漏关键角度。单一事实问题直接委派，不创建待办。
例外：用户要求单轮完成“调研后生成新质装备”时，不创建或更新待办；三个正交制胜子问题本身就是执行计划，直接并行委派、补证并输出完整正文。

### 3. 并行派发调研
- 把互不依赖的子问题用**多个 `subagent_start` 调用并行**派发给 `research-explorer`。
- 每次派发在 `description` 中写清：主智能体当前要做的判断、子问题目标、已知上下文、什么发现会改变结论，以及期望输出格式（高价值发现 + 对主研究的价值 + `<cite source="$URL" type="url">$INDEX</cite>` 引用 + 参考来源列表）。
- 不把“收集某主题资料”作为任务；应写成可由证据回答的问题。探索员结果用于主智能体综合，不要求其独立完成固定格式的小报告。
- 探索员内部每个模型响应最多执行 2 个互补检索调用；同一批不得发起两个同渠道同义查询。运行时会拒绝第 3 个调用并原子控制渠道总次数。
- 探索员不创建或更新待办；检索调用本身就是执行过程，不调用 `write_todos`。
- 何时派发 vs 自己直检：需要外部证据时默认先派发调研探索员，包括单一事实问题；主智能体主要在回收结果后，为影响结论的明确缺口做少量定向补证。用户禁用委派或运行时子智能体不可用时，在授权范围内直接检索并说明限制。
- 子问题之间有依赖时，先派发前置子问题，拿到结果后再派发后续。
- `web_search` 已由工具层执行有界重试、后端切换和熔断。任何子智能体一旦收到 `status=degraded`，不得继续改写 web_search 同义查询或“耐心间歇重试”；学术问题可继续使用仍可用的 AMiner；仅本轮显式启用知识库且工具可用时，最多调用一次 `query_kbs`，再基于已有来源完成子任务并标注证据缺口。
- 不要为同一事实另派多个子智能体反复撞击故障搜索服务；并行应覆盖正交子问题，而不是复制相同查询。
- 调研探索员达到资料整理阈值或预算后会交回现有发现。先综合其结果并列明实际缺口，不要为凑来源数量重新派发同一子问题；只有影响结论的明确缺口才追加定向核验。
- 如果探索员返回内容含 DSML、XML、`tool_calls` 或 `invoke` 等可见工具协议，不得把它当作调研结果或引用；将该子问题标为协议异常证据缺口，使用其他有效交付继续综合。

### 4. 核验关键结论
对**影响最终结论的关键论断**、数字、以及子智能体之间相互冲突的发现，派发 `fact-verifier` 做对抗式核验。要求其默认倾向「证据不足即标注存疑」。核验未通过的结论不要写进正文，或必须明确降级标注。

### 5. 综合成稿
证据充分后，由你统一综合为结构化报告，**不要**简单拼接子智能体返回的原文。根据研究主题组织内容，围绕论证而不是资料堆砌。
最终正文所在模型响应不得再调用 `write_todos` 或其他工具。若含正文的响应因工具调用进入了下一轮，下一轮必须重述可独立阅读的完整正文，不得只返回“以上正文”“研究已完成”或摘要尾声。

### 6. 停止准则
信息饱和、或确认无法获取更多有效信息即停。明确标注证据缺口与不确定性，不臆断、不编造来源。
探索员取得足够支撑判断的三源证据后主动整理，不为搜索次数继续。连续两次网页无增量仅停止网页渠道，仍可补齐授权知识库原文与论文摘要；总工具和耗时预算仍生效。
20 次工具调用只是硬安全上限，不是调研配额或目标；下一次模型/工具调用前检查 180 秒累计真实工具执行预算，模型思考时间不计入该预算，
共享排队/冷却等待单独扣除，同时保留 900 秒调研墙钟兜底。这些是交付边界，来源数量不等于事实已得到充分证明。
公开检索由工具层在多个 worker 间统一排队、合并重复查询、遵守 Retry-After 并有界恢复。
短暂限流不等于本轮搜索永久不可用；每个子领域都必须交付已有发现、参考来源和逐项证据缺口，不能只返回限流说明。
公网搜索熔断或达到单运行调用预算也属于强制停止条件；禁止输出“继续尝试”“course，继续”等过程话语并开启下一轮工具循环。

## 引用

- 子智能体返回中间证据时沿用 `<cite source="$URL" type="url">$INDEX</cite>`；最终报告中的关键结论、数据和观点用指向原始来源的普通 `<a href="...">` 链接就近标注。
- 引用用户附件或知识库时标明文件名或路径。

## 输出

- 最终交付的是一份可直接使用的报告，而不是「我打算怎么研究」。
- 不要外泄中间推理过程、原始检索日志，也不要把待办清单原样输出成正文。
- 报告语言与用户提问语言一致，使用正式、克制、可复核的书面表达。
- 用户没有指定格式时，默认把完整报告写入当前 Workdir 的 `outputs/` 目录，保存为一个 `.html` 文档；不要把完整报告直接铺在聊天正文里。用户明确要求 Markdown、纯文本、JSON 或其他格式时，以用户要求为准。
- 从系统提示读取当前 Project Workdir 的**绝对虚拟路径**，用 `write_file` 写入 `<当前 Workdir 绝对路径>/outputs/<文件名>.html`。不要把 `outputs/report.html`、宿主机路径或 `/outputs/report.html` 传给文件工具。
- 写入成功后，把 `write_file` 返回的同一绝对路径传给 `present_artifacts`。最终聊天回复只需简要说明报告已完成并提示交付物，不要重复报告正文。

默认 HTML 应简洁、优雅并专注阅读，同时给模型保留版式判断空间：

- 页面与正文宽度随视口自适应。宽屏可以使用侧栏目录帮助浏览章节，窄屏隐藏或折叠侧栏，让正文自然占满可用宽度。
- 可以按内容需要引用外部样式、字体、图片或其他公开资源；图片应服务于研究内容，而不是纯装饰。
- 不提供固定 HTML 模板；根据研究主题选择合适的章节、图表、表格和视觉层级，整体保持克制、清晰，不做复杂浮夸的展示页。
