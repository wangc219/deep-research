# Benchmark 测试评判标准

> 版本：v1（当前实际执行口径）  
> 更新日期：2026-07-30  
> 适用范围：装备市场需求深度研究报告的匿名 Pairwise 对比评测  
> 规则来源：`evals/pairwise_prompt_v1.md`、`evals/pairwise.py`、`evals/judging.py`、`evals/aggregate.py`

## 1. 评测目的

Benchmark 比较同一 Query 下两个匿名回答的最终研究质量，重点判断哪一方形成了更可信、更深入、更具军事运用价值和装备发展价值的成果。

评测不判断回答来自哪个系统、模型或 Agent，不奖励系统身份、方法名称、篇幅、标题数量、术语密度、引用数量或格式复杂度。

## 2. 评测对象与盲评方式

每个 Query 的两个参测回答分别匿名为回答 A 和回答 B。

默认同时生成两种顺序：

1. 原顺序：系统甲为 A，系统乙为 B；
2. 反顺序：系统乙为 A，系统甲为 B。

评审专家只能看到：

- Query；
- 匿名回答 A、回答 B；
- 两个回答各自的证据数据中心摘要；
- 匿名 Pair ID。

系统身份映射只保存在管理侧文件中。回答内出现的系统标识会被匿名化处理。

### 2.1 证据数据中心摘要

证据摘要属于回答的正式伴随证据，应与正文一并评判：

- 每个回答最多提供 48 条证据元数据；
- 证据上下文总长度最多 16,000 字符；
- 只保留同时具有 URL 和证据摘要的条目；
- 不得仅按来源数量判优，必须检查证据是否真正支撑关键结论；
- 若未提供独立证据元数据，只依据正文中的显式证据评判。

## 3. 通用评审原则

1. 不推测系统、模型或 Agent 身份。
2. 不因使用“Deep Research”“S1–S6”“制胜机理”等术语而加分。
3. 不因报告更长、标题更多、术语更密集或引用更多而加分。
4. 只评价显式呈现的事实、证据、判断、因果关系、能力需求和验证方案。
5. 完整性参考数量不能替代内容质量，不奖励重复、空泛或为凑数生成的内容。
6. 军事价值在任务效果、能力建设、体系对抗和装备发展层面评价。
7. 不奖励可直接执行的攻击步骤、具体目标选择、实时部署参数等不当操作性内容。
8. 事实、分析推断和待验证假设必须明确区分。
9. 概念设想、实验室结果、样机能力和宣传口径不得直接当作成熟实战能力。

## 4. 五项专项核心标准

以下五项优先用于总体胜负判断，并落实到后续八个评分维度中。

### 4.1 领域属性符合性

判断报告是否真正属于无人远程火力打击装备领域，是否围绕以下任务链环节建立关系：

- 无人化平台或任务载荷；
- 远程作用；
- 侦察定位与目标指示；
- 指挥控制与通信链路；
- 火力投送或毁伤效果；
- 体系协同与保障。

仅泛谈无人化、智能化、远程化或通用技术，不说明其与远程火力打击任务链的关系，不视为符合领域属性。严重偏题应记为硬失败。

### 4.2 装备能力图像

判断是否形成清晰的装备能力图像和作战运用概念，而不是技术名词或装备名称罗列。

至少应覆盖：

- 装备定位与适用任务；
- 典型作战场景和运用方式；
- 在任务链中的作用；
- 核心能力；
- 关键性能和约束；
- 与侦察预警、指挥控制、通信导航、保障等体系的接口；
- 可验证指标。

重点检查以下链条是否贯通：

`任务效果 → 作战运用 → 装备功能 → 性能与约束 → 体系接口 → 装备形态 → 验证指标`

### 4.3 制胜效能

判断是否提出并论证至少一种可信的制胜优势：

1. 当前条件下的颠覆性效能跃升；
2. 传统赛道上的跨代优势；
3. 依托新作战概念开辟新赛道。

必须说明：

- 现有基线或比较对象；
- 效能跃升的作用机理；
- 适用条件；
- 可衡量效果；
- 对手可能采取的反制；
- 优势失效边界。

只使用“颠覆性、跨代、倍增、改变规则”等口号，不构成制胜效能。

### 4.4 创新性

判断核心概念、装备形态、能力组合或运用方式相对现有公开方案是否具有实质新颖性，是否解决既有方案难以解决的关键矛盾。

以下情况不视为创新：

- 简单堆叠热门技术；
- 重新命名已知概念；
- 将现役或在研能力包装为全新方向；
- 未说明与现有方案的差异及优势来源。

### 4.5 可实现性与成熟度

重点检查：

- 技术成熟度；
- 工程集成难度；
- 关键部件和供应约束；
- 体系兼容性；
- 成本与保障条件；
- 试验验证条件；
- 实现时间尺度；
- 分阶段发展和验证路线。

关键事实、性能数字、成熟度等级和效能结论必须有可靠依据。伪造来源、虚构参数或过度外推影响核心结论时，应记为硬失败。

## 5. 路径识别与规定产物

评审专家首先依据 Query 独立识别主要研究路径，不能直接接受回答对自身路径的声明。

| 路径 | 研究类型 | 核心逻辑 |
| --- | --- | --- |
| A | 新作战战法发现 | 新战法/新概念 → 效果推演 → 装备能力需求 |
| B | 传统能力缺口发现 | 场景与现有战法 → 装备能力映射 → 现状对标 → 差距识别 |
| C | 局部战争案例经验发现 | 案例事实 → 决策点与因果链 → 跨案例规律 → 未来场景 → 装备需求 |
| D | 技术驱动发现 | 前沿技术 → 成熟度与潜力 → 颠覆场景 → 装备形态与能力需求 |
| E | 对手动向牵引发现 | 对手装备/演习/条令变化 → 威胁效应 → 对冲与反制需求 |
| F | 体系对抗博弈发现 | 体系建模 → 耦合与脆弱点 → 补链强链 → 体系级装备能力 |
| G | 跨域融合发现 | 多域接口 → 协同缝隙 → 跨域装备能力 |
| H | 非传统安全牵引 | 新型威胁 → 新场景 → 对手画像 → 突破方向与装备需求 |
| OTHER | 动态组合路径 | 无法归入单一路径或需要多路径组合 |

### 5.1 A 路径重点产物

- 现有战法或任务链局限；
- 真正不同的新战法；
- 作用机理、效果链、适用场景和失败条件；
- 不同战法及其组合比较；
- 战法到装备功能、体系接口和能力指标的映射；
- 可验证的装备形态建议。

完整性参考：3 种新战法、5 种战法组合、8 大能力域、约 30 项有效能力指标。数量仅作参考，不作为机械评分要求。

### 5.2 B 路径重点产物

- 任务背景和作战场景；
- 对手体系、现有战法和任务链约束；
- `任务效果 → 装备功能 → 性能/约束` 映射；
- 能力空白、关键差距、部分差距、基本满足和相对优势的区分；
- 现役、在研、体系接口、保障条件和成熟度分析；
- 跨场景聚合、去重和优先级排序；
- 需求卡片、能力全景或能力组合及可追溯报告。

### 5.3 C 路径重点产物

- 区分事实、报道、分析判断和推测；
- 关键事件时序和决策点；
- 有证据支持的因果链；
- 跨案例比较；
- 规律迁移的相似条件和失效条件；
- 从案例规律到装备发展需求的转化。

完整性参考：6 条实质性规律、3 类高置信未来场景、覆盖 4 类新兴装备方向的需求图像。

### 5.4 D—H 路径重点产物

- 驱动因素或威胁依据；
- 场景或体系影响；
- 因果与任务效果分析；
- 能力缺口或突破方向；
- 装备功能与体系接口；
- 验证路线；
- 风险与成熟度边界。

## 6. 八个 Pairwise 评判维度

每个维度分别输出 `A`、`B` 或 `tie`。

| 维度 | 权重 | 主要评判内容 |
| --- | ---: | --- |
| 路径与任务完成度 `route_task_fulfillment` | 10% | 路径是否适配；是否完整回答 Query；是否交付路径核心产物；是否符合无人远程火力打击领域属性 |
| 证据与事实可靠性 `evidence_and_factuality` | 5% | 关键事实、引用、数字、成熟度与效能判断是否可靠、相关、可追溯；是否区分事实、推断和假设 |
| 因果与机理深度 `causal_and_mechanism_depth` | 15% | 是否贯通背景、场景、对手/体系薄弱点、任务效果、制胜机理、突破方向与能力需求；是否有基线、权衡、反证和失败条件 |
| 军事作战价值 `military_operational_value` | 20% | 是否形成明确作战运用概念；是否对侦察、决策、协同、远程火力、突防打击、反制威慑、生存保障等产生具体价值；是否有可信制胜效能 |
| 能力映射与需求质量 `capability_mapping_and_demand_quality` | 20% | 装备能力图像是否具体完整；任务效果到验证指标的映射是否贯通；是否区分现役升级、新装备、体系补链和非装备约束；优先级是否有依据 |
| 新颖性与前瞻性 `novelty_and_foresight` | 15% | 是否相对现有方案有实质差异；是否解决关键矛盾；是否说明实现条件、时间尺度、成本代价和风险 |
| 体系与跨场景稳健性 `system_and_cross_scenario_robustness` | 5% | 是否覆盖多场景和多对抗视角；是否聚合、去重和排序；优势在反制、链路受扰和保障受限时是否成立 |
| 不确定性与验证 `uncertainty_and_validation` | 10% | 是否披露未知、假设、替代解释、冲突和证据边界；是否客观判断成熟度和工程约束；是否提出阶段路线、试验路径和反证条件 |

权重合计为 100%。

> 重要说明：这些权重用于指导评审专家判断重要性，但当前聚合程序不把八个维度机械换算成数值总分。总体胜者由专项核心标准和核心维度的实质差异决定。

## 7. 总体胜者判定

评审专家先比较五项专项核心标准，再综合以下核心维度：

- 路径与任务完成度；
- 证据与事实可靠性；
- 因果与机理深度；
- 军事作战价值；
- 能力映射与需求质量。

判定规则：

1. 一方在专项核心标准或核心维度具有明确、实质性优势，应判其总体胜出。
2. 创新性不能抵消领域偏离、证据失实或明显不可实现。
3. 成熟性不能替代制胜效能和创新价值，不能奖励缺乏优势的常规拼装。
4. 只有双方在领域符合性、装备能力图像、制胜效能、创新性、成熟度、证据质量和分析深度方面实质相当，才判 `tie`。
5. 总体胜负不得按篇幅或维度获胜数量机械决定。

评审同时给出：

- 总体置信度 `confidence`：0—1；
- 路径识别置信度 `route_confidence`：0—1；
- 偏好强度 `preference_strength`：`slight`、`moderate` 或 `strong`。

## 8. 硬失败规则

以下情况应记录在 `hard_failures` 中：

1. 伪造、错配或明显不存在的来源；
2. 关键事实明显错误；
3. 将无依据推测表述为确定事实；
4. 使用虚构数字、概率或效能提升比例支撑核心结论；
5. 主要结论与 Query 无关；
6. 核心方案不属于目标装备领域，且未建立有效任务链关系；
7. 缺失所选研究路径的核心产物；
8. 装备需求只是技术名词或装备清单，没有任务和能力映射；
9. 未形成装备能力图像或作战运用概念，却声称具有明确装备发展价值；
10. 没有比较基线、作用机理或证据，却宣称颠覆性、跨代或开辟新赛道；
11. 将现役或在研能力错误描述为完全空白；
12. 将概念、实验室验证或样机能力错误描述为成熟装备或已形成实战能力；
13. 提供不当的可执行攻击步骤、具体目标选择或实时部署参数。

硬失败不会由报告篇幅、排版或普通表达问题触发。

## 9. 人工仲裁规则

满足任一条件时进入人工仲裁队列：

- 总体置信度低于 0.65；
- 路径识别置信度低于 0.65；
- 不同评审专家或正反顺序判断不一致；
- 存在引用问题；
- 存在硬失败；
- 关键事实或引用需要外部核验；
- 双方分别在不同核心维度占明显优势；
- 疑似严重失败但无法确认；
- 双方对任务路径理解明显不同；
- 评审专家主动要求仲裁。

## 10. 聚合与统计方法

### 10.1 单个 Query 的胜者

同一 Query 下可能包含正序、反序以及多个独立评审专家的判断。

聚合程序按总体胜者票数统计：

- 某系统获得唯一最高的非平局票数，则该系统赢得该 Query；
- 两个系统的最高非平局票数相同，则该 Query 记为平局；
- 所有判断均为平局，则该 Query 记为平局。

维度结果单独汇总为 `dimension_votes`，不直接替代总体胜者票。

### 10.2 系统得分率

对每个 Query 计分：

- 胜：1 分；
- 平：0.5 分；
- 负：0 分。

系统得分率：

`score_rate = 所有 Query 得分的算术平均值`

同时输出：

- 胜、平、负数量；
- 得分率；
- Bootstrap 95% 置信区间；
- 各维度胜负票数；
- 硬失败统计；
- 人工仲裁队列；
- 完成率、平均运行时间、平均估算成本和平均用量。

Bootstrap 重采样次数按入口配置：当前 Benchmark Web 与消融 Web 使用 500 次，CLI `aggregate` 默认使用 5,000 次，离线 smoke 使用 200 次；聚合函数最低执行 100 次。

## 11. 当前结果的正确解读

1. `score_rate` 是按 Query 胜平负计算的总体对比得分率，不是八维加权分数。
2. 八维权重表达评判优先级，不代表聚合器会执行加权求和。
3. 置信区间反映当前 Query 样本下得分率的不确定性。
4. Pairwise 胜率只能说明相对于指定对手的表现，不能直接解释为绝对质量分。
5. 存在硬失败、引用问题或低置信判断时，应结合人工仲裁结果解释。
6. Test 集、自定义评审 Prompt 或自定义模型产生的结果应标明实验条件，不能与不同配置结果直接混用。

## 13. 当前未设置的规则

当前实现没有设置统一的“得分率达到多少即验收通过”的自动门槛。系统输出胜平负、得分率、置信区间、维度票数、硬失败和仲裁队列，由项目验收方结合实验设计确定最终通过标准。
