# 项目进展周报

## 一、本周工作进展

本周主要围绕系统总体架构和核心业务流程开展设计工作，形成了项目架构设计初稿，主要完成内容如下：

1. 梳理了系统的两类运行模式，即专家模式和智能模式，明确了不同输入条件下的任务启动方式。
2. 初步构建了JS装备需求挖掘的业务逻辑，形成“形势分析—国际形势分析、ZZ场景推演—制胜机理分析—ZB能力映射—现状对齐—需求图像生成”的总体流程。
3. 完善了需求挖掘方向，涵盖新战法发现、传统能力缺口发现、局部案例经验、技术驱动、对手动向牵引、体系对抗、跨域融合和非传统安全等八类路径，无法命中按需组合生成蓝图。
4. 初步完成多智能体体系设计，明确主控chief智能体、国际形势分析智能体、ZZ场景智能体、制胜机理分析智能体和案例研究智能体等角色及职责。
5. 对深度搜索、深度研究、知识操作、推演仿真、认知推理和成果生成等基础 Skill 能力进行了分类梳理。
6. 初步明确 Benchmark 的测试集构成、Baseline、消融实验、Pairwise 评测指标和验收标准，为后续验证多智能体方案效果提供依据。
7. 启动 Benchmark的小规模资料采集和 Query 生成，优先构建八分支输入测试集。

## 二、阶段成果

- 已形成八类需求挖掘路径及其差异化处理重点。
- 已形成S1—S6制胜机理分析链和回溯、跳步、并行执行思路。
- 已明确需求卡片、能力全景图和深度研究报告等主要成果形式。
- 已明确与商业 Deep Research、通用 Agent、单模型方案的对比思路，以及领域智能体、动态规划、突破性推理和自适应反馈等关键消融方向。

## 三、当前问题

- 各智能体的输入、输出及数据接口仍需进一步标准化。
- 不同挖掘路径的任务编排和循环终止条件需要细化。
- ZZ库、案例库、条令库等知识数据来源和更新机制尚需明确。
- 推演结果、证据可信度和需求优先级的评价指标有待建立。
- Query 专家筛选、隐藏评分 Rubric、评测 Judge 和人工复核机制仍需进一步落实。

## 四、下周工作计划

1. 细化主控智能体的任务解析、路径选择和动态编排规则。
2. 明确各业务智能体及子智能体的输入输出规范。
3. 选择一类典型需求场景，开展最小可行流程设计和原型验证。
4. 设计需求卡片、证据链和能力需求图像的数据结构。
5. 进一步完善系统技术架构、知识库方案及效果评估指标。

## 五、后期重点

1. **完善系统原型：** 打通任务解析、分支识别、动态编排、深度搜索、反思回溯和成果输出的最小闭环。
2. **建设评测数据：** 按八类分支采集公开、合法、非涉密资料，完成清洗去重、资料聚类和安全过滤，逐步形成候选 Query 池。
3. **组织专家评审：** 建立 Query 分类、改写、难度定级、安全审查和交叉复核机制，形成可追溯的正式测试集。
4. **开展对比实验：** 落地 Commercial-DR、Generic-Agent、Direct-LLM 等 Baseline，并实施领域智能体、动态规划、S3突破推理和自适应反馈消融实验。
5. **建立评价闭环：** 围绕任务满足度、事实正确性、引用质量、分支分析能力、完整性和清晰度开展匿名 Pairwise 评测
