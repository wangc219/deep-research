# JS装备市场需求深度挖掘系统——甲方汇报事实底稿

> 口径日期：2026-07-22。本文只汇总项目仓库内已有设计、实现、验收记录与真实 Benchmark 结果，用于制作项目成果汇报 PPT。

## 1. 项目目标与业务价值

- 面向公开、非操作性、任务级和能力级的 JS 装备市场需求挖掘。
- 把传统的“资料检索 + 人工归纳”升级为“任务解析—路径选择—多智能体研究—证据治理—制胜机理推理—能力画像—审计交付”的可追溯闭环。
- 支持专家模式与智能模式；支持三条已落地研究路线，并以 A-H 八类发现分支作为目标架构扩展层。
- 最终交付不是装备清单，而是具备任务背景、作战效果、能力功能、性能约束、体系接口、装备形态、优先级、证据链和验证路径的能力画像。

## 2. 已落地的核心能力

### 2.1 业务路径与动态编排

- 已落地三条可执行路线：新制胜机理、传统能力缺口、局部战争案例。
- 已实现 A-H 八类发现分支的识别、映射与有界元编排：新战法、传统缺口、案例经验、技术驱动、对手动向、体系对抗、跨域融合、非传统安全。
- 主控 Agent 可根据任务主题、交互模式和分支选择业务 Agent，补齐能力覆盖，并形成差异化执行蓝图。

### 2.2 多智能体 Harness

- 动态 Agent Registry：默认角色可全选、选子集或通过配置替换，不在编排器中写死。
- 每个 Agent 使用独立上下文投影、工具权限、预算、Session、Checkpoint 和输出目录。
- 支持有界并发 Wave 与 Subagent map-reduce；支持独立会话、结构化交接和失败恢复。
- 已实现 S1-S6 专用 Agent：对手分析、作战运用审查、突破口思考、装备能力映射、装备现状与差距、能力图像综合。
- 已实现 L1 内循环、L2 中循环、L3 外循环与 L4 元循环，按缺口定向补证、回溯或调整执行强度。

### 2.3 证据治理与审计交付

- 公开来源检索、SSRF 防护、页面正文简化、位置索引、材料化、质量评分与正式证据门控。
- 事实、推断与假设分离；低质量或材料化失败来源不进入正式支撑链。
- 支持持久化 SSE 事件、断线重放、最小权限、基础 RBAC 和 Agent 原始会话隔离。
- 自动生成报告、需求卡片、能力全景图、推理追溯、质量门控、架构验收、交付 Manifest 与 SHA-256 校验。

### 2.4 企业运行闭环与工作台

- FastAPI + SQLite/SQLAlchemy 持久化队列 + 独立 Worker + React/Vite 工作台。
- 工作台覆盖：研究创建、草稿编辑、状态筛选、软归档、执行历史、实时交互、证据中心、S1-S6、能力画像、报告评审、Benchmark。
- 已有真实工作台数据：页面展示 24 项完成任务；支持多任务并行槽位；真实任务可查看 327 条交互事件、24 项证据索引、6 个 S 节点和 L1-L3 门控结果。

## 3. 工程与验收成果

- 2026-07-17 补充验收记录：全量回归 `446 passed`；Vite 生产构建、Compose 配置和本轮 Ruff 检查通过。
- 真实三路线多模型验收：三条路线均达到 `status=completed`、`runtime_complete=true`、`release_ready=true`、`audit_status=approved`、`formal_evidence_present=true`。
- 企业前后端闭环已验证：API 创建任务、持久化队列、独立 Worker 消费、跨进程状态读取、证据/S1-S6/能力画像/报告展示、Manifest 完整性校验。
- 代表性闭环验收记录：4 路基线 Agent、6 个推理节点、L1/L2/L3 三阶段、2 项九字段能力画像、71 条交互事件、15/15 工具调用/结果、30 个 Manifest 文件。

## 4. Benchmark 体系建设

### 4.1 Benchmark v1.0 数据资产

- 形成双层 Benchmark：三条可执行路线用于工程回归，A-H 八类分支用于目标架构评估。
- 正式案例 480 条：A-H 每分支 60 条。
- 数据划分：Dev 120 / Validation 120 / Test 240。
- 专家深金标 72 条：每分支 9 条，配离线证据包。
- 专家模式 240 条 / 智能模式 240 条；中文 432 条 / 中英混合 48 条。
- 覆盖 10 类领域，每类 48 条；四档时间跨度各 120 条。
- 每分支 45 条标准案例 + 15 条压力案例，压力类型覆盖跨分支、歧义输入、证据冲突、噪声矛盾、Agent 缺失/Recall 和安全提示注入。
- 防泄漏检查 72,000 对案例，Jaccard 阈值 0.86，违规 0，最高近邻相似度 0.8191。

### 4.2 最新真实 Pairwise Benchmark（2026-07-22）

- 评测集：19 条专业 Query；完整方法、通用 Codex Agent、纯 LLM 三系统。
- 运行结果：57/57 完成；项目方法与两个 Baseline 均为 100% 完成率。
- 盲化 Pairwise：对通用 Agent 72 次评审判定；对纯 LLM 76 次评审判定；2 名真实专家 Judge。
- 对纯 LLM：完整方法 19 胜 0 平 0 负，得分率 100%，95% CI 100%-100%。
- 对通用 Codex Agent：完整方法 17 胜 2 平 0 负，得分率 94.74%，95% CI 86.84%-100%。
- 对通用 Agent 的分维度票型（完整方法 : 平 : 通用 Agent）：
  - 能力映射与需求质量：65 : 2 : 5
  - 因果与机理深度：69 : 2 : 1
  - 军事运用价值：65 : 6 : 1
  - 前瞻新颖性：62 : 10 : 0
  - 路径与任务完成：60 : 4 : 8
  - 体系与跨场景稳健性：70 : 2 : 0
  - 不确定性与验证：66 : 4 : 2
  - 证据与事实可靠性：2 : 3 : 67
- 对纯 LLM 的分维度票型显示完整方法在因果机理、前瞻新颖性、能力映射、军事价值和路径完成度上均形成压倒性优势。

### 4.3 Benchmark 揭示的改进方向

- 质量优势已经被真实盲评验证，核心特色集中在机理深度、军事价值、能力映射、跨场景稳健性和前瞻性。
- 与通用 Agent 相比，“证据与事实可靠性”明显落后，是下一阶段首要改进项：需要提高引用与结论的直接对应性、正文可核查来源呈现、时效校验和冲突证据处理。
- 最新 19 条真实评测中，完整方法平均耗时 1188.604 秒（约 19.8 分钟），通用 Agent 226.728 秒，纯 LLM 138.874 秒。当前应把“高质量方法的工程提速”作为下一阶段专项，而不应把设计期性能预期当作已实测结果。
- 当前 19 条 Query 多数进入人工仲裁队列，主要原因包括 Judge/顺序分歧和引用问题；后续需完善仲裁收敛、引用审计与专家复核机制。

## 5. 项目特色总结

1. 不是通用 Deep Research 套壳，而是把 JS 装备需求业务逻辑固化为路线、分支、S1-S6、能力画像和质量门控。
2. 不是单 Agent 长文本生成，而是独立受控会话、多角色证据研究、动态编排和有界循环。
3. 不是只输出报告，而是同步输出结构化需求卡片、能力全景、证据链、推理追溯、运行事件和可校验交付包。
4. 不是黑箱宣称效果，而是形成 480 条分层案例、72 条深金标、真实 Pairwise 盲评和 Benchmark 工作台。
5. 已经形成“业务闭环 + 工程闭环 + 评测闭环”，下一阶段重点从功能建设转向证据可信度、效率和目标环境投产验证。

## 6. 甲方汇报建议口径

- 主结论：核心业务闭环已经落地，并在真实盲评中证明了相对通用方案的显著质量优势。
- 成果重点：三路线、A-H 元编排、S1-S6、L1-L4、证据治理、能力画像、企业工作台、Benchmark 数据资产。
- 风险透明：证据事实可靠性和运行效率尚未达到最终目标，应作为下一阶段验收与优化重点。
- 下一阶段建议：引用/事实专项、Benchmark 扩面至 Full-480 与 DeepGold-72、性能提速、正式基础设施适配、专家仲裁闭环、现场试点。
