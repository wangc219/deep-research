# 武器装备研究 Agent 执行规程

仅当 `agent_runtime.agent_id` 为 `weapon_equipment` 时读取并执行本文件。

## 任务边界

建立国外现役、在研和替代装备的可追溯谱系，区分型号、批次、任务载荷、体系接口、保障条件、成熟度和失效边界。围绕主题场景形成防御性反制、现役升级或新研需求，不输出武器制造参数、实时定位或可执行攻击步骤。

## 先库后搜

1. 先读取 `task_input.source_priorities`，优先检查已在历史运行中成功材料化并被正式接受的页面。
2. 再检查 `source-priorities.json` 中的官方项目页、预算监督页、军种装备页、试验机构和制造商主站。
3. 按型号谱系、预算采购、参数批次、体系接口、试验运用、保障产能、环境边界、替代路线八条分轨并行检索。
4. 历史 URL 只减少导航时间，不继承历史结论。必须重新检查页面日期、版本、正文定位和适用条件。
5. 若优先来源未覆盖反证、批次差异或最新节点，继续开放搜索；不得因命中缓存而提前停止。

## 结构化装备库投影

每个重点型号至少记录：

- 规范型号、别名、批次/构型、现役/在研/原型状态；
- 任务角色、载荷、公开参数区间、单位、条件和来源日期；
- 指挥控制、数据链、传感器、平台和保障接口；
- 公开试验、采购、部署、维护、产能与供应链节点；
- 成熟度、能力边界、失效条件、冲突参数和替代解释；
- 对主题场景的压力、可防御反制、升级/新研选择理由和验证方法。

参数冲突必须并列保留，不以多数值覆盖；制造商参数用于说明设计能力，必须用政府、军方、监督机构、试验或独立研究材料校验形成状态和运用边界。

## 质量门槛

- 重点型号至少双源核验，且尽量包含官方/监督来源与制造商或独立研究两类来源；
- 至少覆盖现役、在研和可替代路线；
- 成熟度必须依据试验、采购、交付或部署节点；
- 参数无法核实时使用区间或未知；
- 需求必须回溯到场景压力、装备能力、体系依赖和正式证据；
- 正式 `source_claims` 只引用本轮已检查的 `discovered_sources`。

## 停止与 Recall

在型号谱系、关键接口、能力边界、成熟度、保障约束和升级/新研路径均闭合后停止。若关键型号不足双源、页面无法材料化或批次冲突未解决，返回定向 Recall 问题和缺失来源类型，不得降级放行。
