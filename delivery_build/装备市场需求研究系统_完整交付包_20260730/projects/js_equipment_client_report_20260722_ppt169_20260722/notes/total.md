# 01_项目阶段成果汇报

本次汇报围绕基于多智能体协作的 JS 装备市场需求深度挖掘系统，重点展示已经完成的落地功能、工程验收和 Benchmark Baseline 结果。项目已经从架构设计进入可运行、可追溯、可评测的系统初版阶段。下面先用一页概览说明项目完成度。

---

# 02_执行摘要

当前项目已经形成业务、工程和评测三类闭环。核心功能覆盖三路线与 A 到 H 动态编排、S 一到 S 六专业推理链、证据门控与交互审计，以及成果矩阵和交付 Manifest；全量回归达到四百四十六项通过，对通用 Codex Agent 的真实专家盲评为十七胜、两平、零负。接下来我们从端到端业务流程看这些能力如何串联。

---

# 03_七阶段业务闭环

系统把传统的资料检索和人工归纳，升级为七阶段可追溯研究闭环。任务从解析和路线选择开始，经过多智能体研究、证据治理和专业机理推理，最终形成成果画像与审计交付，并通过验证回流再次核查证据。这个闭环保证交付不是简单清单，而是带有背景、约束、证据和验证路径的结构化成果。

---

# 04_项目适配总体架构

这一页用 Codex 原生绘制的可编辑架构图，把项目业务和功能收敛为一条清晰主线路。任务入口经过三路线和 A 到 H 分支形成研究蓝图，主控 Agent 调度路线与分支专用 Agent，再进入 S 一到 S 六推理链；证据治理层在门控未通过时定向回溯到相关 Agent，企业运行层最终通过接口、队列、Worker、工作台、Trace 与 Manifest 完成交付。下面进一步展开三路线和动态分支的编排机制。

---

# 05_三路线与八分支

系统已经落地新制胜机理、传统能力缺口和局部战争案例三条稳定路线，同时以 A 到 H 八个分支形成目标架构扩展面。主控 Agent 根据任务主题、交互模式和覆盖缺口选择专业 Agent，并生成差异化研究蓝图。这样既保证成熟路径稳定执行，也保留面向新任务的动态发现能力。

---

# 06_可治理的多智能体协作

多智能体在本项目中不是简单地重复调用模型，而是运行在受控 Harness 中。Agent 角色可通过 Registry 动态选择或替换，每个 Agent 拥有独立 Session、上下文、工具权限、预算、Checkpoint 和输出目录，并通过有界 Wave 并发和结构化交接实现可恢复协作。接下来介绍这些 Agent 所固化的专业推理链。

---

# 07_S1到S6专业推理链

S 一到 S 六把研究材料逐级转化为机理分析和能力成果。六个节点分别覆盖对手分析、运用审查、突破口思考、能力映射、现状差距和综合输出，使规律、场景、因果、能力需求、指标边界和验证建议形成连续链路。专业推理链之外，系统还设计了分层质量循环来处理证据不足和阶段矛盾。

---

# 08_L1到L4质量循环

L 一到 L 四按照缺口大小触发不同范围的纠偏。系统可以在当前节点补证、回溯相邻阶段、跨阶段重新门控，并在收敛后进行有界复核；所有调整都受到 Harness 边界约束并保留触发和动作记录。这样既能提高质量，又避免无限反思和不可控重编排。

---

# 09_证据治理与审计交付

证据治理贯穿检索、材料化、质量评分、引用和最终交付。只有通过安全约束和质量门控的来源才能进入正式支撑链，低质量或材料化失败的来源会被明确分流；报告、成果画像、推理追溯、交互事件和 Manifest 则共同构成可复核交付栈。下面通过真实系统界面展示这些能力已经如何产品化。

---

# 10_研究指挥台

研究指挥台已经承载真实任务创建、排队、执行、筛选、归档和历史查看。接口创建任务后由持久化队列和独立 Worker 跨进程执行，应用重启后仍可读取摘要、证据、专业节点、成果、报告、追溯与 Manifest。它证明项目已经从算法流程进入可操作的企业工作台形态。

---

# 11_交互与审计界面

真实任务已经记录三百七十二条交互事件、二十二张证据卡、六个专用 S Agent、十二个推理节点和一次真实 Recall。页面中的真实审计链清楚显示 L 一门控未通过，系统发起定向补证，完成再调后返回 L 一，并由主控 Agent 合并结果、重新计算能力覆盖。持久化事件流同时支持实时观察、断线重放和事后审计，下一页进一步看专业推理结果在产品中的呈现。

---

# 12_架构执行总览

这一页用真实前端展示架构执行总览。顶部六个状态块对应任务理解、多源基线研究、发现结果收敛、S 一到 S 六专用 Agent、独立审计和报告交付；中部完整列出六个专用 Agent 及其本轮结果，下部展示 L 一到 L 四步骤门控、因果复核、残差回溯和元循环的执行次数与最近状态。页面最下方还展示本次由主控 Agent 根据 A 到 H 分支和当前输入动态选取的业务 Agent，因此从发现蓝图到专用推理、循环治理和业务协作的执行状态都能够被查看和回放。

# 13_成果交付矩阵

系统已经把研究结论沉淀为甲方可直接评审的多形态成果交付包。真实能力成果界面之外，交付矩阵还包括深度报告、需求卡片、能力全景、推理追溯、证据索引、质量门控、交互审计和 Manifest。整个交付包既支持当前评审，也为后续验证和迭代保留依据。

# 14_工程验收结果

工程侧全量回归达到四百四十六项通过，生产构建、配置和代码检查均通过。三条真实路线均达到完成、运行闭环、可发布、审计批准和正式证据存在的验收状态，代表性闭环还覆盖四路 Agent、六个推理节点、七十一条事件、十五项工具结果和三十个 Manifest 文件。除了工程验收，项目还建设了可持续扩展的 Benchmark 数据资产。

---

# 15_Benchmark数据资产

正式 Benchmark 不会把四百八十条候选题库直接全部运行，而是由专家从中筛选并标注约一百条真正适合 Deep Research 的 Query，最终数量以专家终审为准。评测采用同题匿名 A/B Pairwise 盲评：Judge 不推测系统身份，先独立识别 A 到 H 或 OTHER 主路径并检查该路径规定产物，再从任务完成、证据事实、机理深度、军事价值、能力映射、前瞻性、跨场景稳健性、不确定性与验证、沟通效率九个维度比较两个回答。前五项核心维度各占百分之十五，总体胜者不按篇幅、术语密度或维度票数机械决定；只有核心质量实质相当才判平局。总体或路径置信度低于零点六五、引用需要核验、双方在不同核心维度各有明显优势或疑似严重失败时，结果自动进入人工仲裁，并以结构化 JSON 留存胜者、置信度、缺项、引用问题和仲裁原因。

---

# 16_Baseline真实盲评

这一页是本次汇报的核心实证。十九条专业 Query 全部完成，经过两名真实专家盲评，完整方法对纯 LLM 为十九胜、零平、零负，对通用 Codex Agent 为十七胜、两平、零负；八维票型显示能力映射、机理深度、军事价值、前瞻性、任务完成、跨场景稳健性和不确定性处理七项优势。证据与事实可靠性的票型为二比三比六十七，但结合报告声明十九项正式证据而正文没有完整展开的情况，这一结果更应理解为正文证据展示、评测输入口径和 Judge 可见信息的差异，不能直接推导为底层证据不足。

---

# 17_下一阶段建议

下一阶段重点集中在三件事。第一，继续优化智能体设计和协作编排，细化主控、专用 Agent、业务 Agent 与 S1 到 S6 的职责边界，完善动态路由、并行协同、回溯再调和输入输出契约。第二，进一步梳理和完善端到端业务执行流程，让任务入口、三路线、A 到 H 分支、六步推理、证据门控、人工复核和成果交付保持一致，并补齐异常处理与状态回放。第三，持续完善 Benchmark 测试，扩充专家标注 Query，优化匿名 Pairwise 盲评和人工仲裁，同时增加主控编排、专用 Agent、S1 到 S6、证据门控、Recall 与工具链等模块的消融实验，量化各模块的实际贡献。
