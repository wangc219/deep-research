# 企业交付成熟度审计与演进建议

审计日期：2026-07-13。

## 1. 审计结论

当前代码已经达到“首版可部署、可演示、可审计”的交付标准：三条研究路线、动态基线 Agent、差异化上下文与权限、制胜机理六步推理和 L1/L2/L3、定向再调、五判据、文字能力画像、API/worker/Web、恢复与交付清单均从主链可达。

本轮进一步接通两项关键能力：

- Real 模式使用 Responses `web_search` 执行公开资料检索，返回的来源必须继续经过本地 SSRF 防护、材料化、正文段落定位、质量评分和正式证据门控。
- runner、worker、共享事件表、SSE 和 Web 时间线形成实时交互通道；运行中可查看任务委派、搜索、抓取、证据评分、保存点、制胜机理推理、再调、审计和报告事件，断线后可按事件序号重放。
- 工作台任务生命周期增加创建、草稿更新、软归档、历史筛选和完整事件历史；Real 草稿直接配置模型、URL 和密钥引用。
- 三条研究路线的能力画像和报告问题链已差异化，最终直接回答需要发展或升级哪些产品功能。

当前不应表述为“生产高可用平台已经全部完成”。OIDC、TLS、PostgreSQL/Redis 高可用、数据库迁移体系、多 worker 租约与故障接管、备份恢复、容量压测和目标终端视觉签字仍需要结合目标环境基础设施实施或复验。

## 3. 企业级缺口与优先级

### P0：投产前必须完成

1. 在目标网络与凭据环境执行 Real smoke，验证模型网关、`web_search`、出口代理、材料化和证据门控的完整链路。
2. 接入目标环境 OIDC/统一身份，禁止在生产环境信任浏览器可伪造的 `X-Role`。
3. 配置 TLS、反向代理、安全响应头、访问日志脱敏和密钥管理系统。
4. 建立数据库迁移和版本回滚流程；生产数据库切换到 PostgreSQL。
5. 完成备份恢复演练、故障注入、容量压测和目标浏览器视觉验收。

### P1：规模化运行前完成

1. 将 SQL 队列升级为带 worker identity、租约、心跳、超时重领和重试策略的任务队列，避免 worker 异常退出后任务长期停留在 claimed 状态。
2. 建立搜索与模型预算控制：每任务最大检索次数、来源数、token、时间和费用；超限进入可审计降级。
3. 增加证据主张级校验：从“来源可访问且质量合格”升级为“引用段落与具体 claim 的语义支撑度可解释”。
4. 增加人工评审工作流：分析师确认、退回补证、版本发布和报告签署。
5. 建立前端 Vitest/Playwright、可访问性、三视口截图基线和长时间 SSE 稳定性测试。

### P2：能力持续演进

1. 在保持联网优先的前提下增加本地文档检索适配器，并沿用同一 EvidenceCard 和权限模型。
2. 建立领域评测集：按三条路线评价证据覆盖、冲突发现、能力画像可用性和专家一致性。
3. 支持 Agent/Prompt/工具版本登记与 A/B 评估，使能力提升可度量、可回滚。
4. 增加组合研究与跨任务复用，但只复用已审计的证据索引和摘要，不共享原始 session。
