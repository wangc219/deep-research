三、总体方案

（一）总体架构
本栏不把“智能巡飞精打”写成统一软件壳，而是收敛为三层共享边界：外部体系只下达任务区、打击约束、发射授权和回收/中止规则；弹药本体必须独立承担末端感知、降级导航、航迹保持、命中判别与安全中止；若采用协同，则只共享局部态势、剩余能量、目标分配和攻击次序，不能把持续联网、全程重规划或外部持续指示当成本体能力。这样，在GNSS受扰、链路间歇和欺骗目标并存时，任务结果不会随单点失联整体失效。

各型装备的分工应按接敌几何和末端机理区分，而不是塞进同一套通用指标。群栖自组型的核心在群内状态同步和失链后接续攻击，成败取决于弹体群能否在压制环境下维持目标选择、轮换和损毁评估；蜂簇接力型依赖载体释放顺序与前后波次接口，前导单元先消耗拦截资源，后续单元再补毁，任何释放失序都会把穿透压力降回单弹水平；气膜掠波型把低空贴海稳定飞行作为本体门槛，真正改变战果的是海面背景下的末端识别与抗拦截时序；形记忆折展、磁流体矢控和双体耦合分别通过翼面重构、侧向矢量重分配和前后体分工压缩拦截窗口，体系只需提供通用装载与任务装订，不应把各自机动机理抽成公共模块；“玄礁”则把水下隐蔽与出水末攻拆成两段状态转换，最脆弱的是出水瞬间的识别切换和时序控制。

因此，总体架构的优先顺序不是堆叠功能，而是先固化发射兼容、失链保持、降级导航和安全中止，再谈群协同与模块扩展；凡是只能在理想网络和完整态势下成立的能力，都不应上提为总体方案的公共层。
