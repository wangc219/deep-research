## 三、总体方案

### （一）总体架构

本项目不按“单平台对单目标”设计，而是按“分布式感知节点 + 低成本精确火力 + 无人协同控制 + 弱网降级运行”组织。它要解决的矛盾很直接：高强度海空对抗里，敌方会用干扰、诱饵、机动转移和分层防空打断我方任务链，单个无人平台或单枚低成本弹药即便数量增加，也不会自动形成连续发现、持续跟踪和接续打击能力。公开资料显示，美军在反无人战略、Replicator和海军陆战队分布式作战/EABO中，已经把“可消耗系统、协同自治、抗干扰韧性、开放架构”作为核心方向，这说明未来竞争重点不在单件平台性能，而在接口、任务网络和降级闭环。

因此总体架构采用“前沿无人节点负责发现与诱导、边缘控制节点负责筛选与授权、火力节点负责精确打击、评估节点负责战果回传与二次分配”的四层结构。这样做的直接收益不是把火力做得更大，而是把任务链拆短：在敌方通信压制和目标快速机动条件下，仍能维持局部可用的发现-决策-打击闭环。若链路受损，系统不追求全局最优，而是退化为局部自治、小群协同、单节点自决的最低可用模式，避免“看见了打不到、打到了跟不上、打完了不知是否命中”的失效。

### （二）子系统方案

子系统设计围绕“少量接口方向、可验证、可降级”展开，不追求一次性堆叠全部能力，而是优先补齐海空交界层的任务缝隙。

| 子系统 | 主要输入 | 主要输出 | 解决的问题 | 失效边界 |
|---|---|---|---|---|
| 平台层 | 海空前沿态势、航路约束、回收条件 | 无人载体、消耗型载荷、前置布设点位 | 把火力和感知前推到敌方突防窗口前沿 | 若平台不能完成自主返航或低成本弃置，则不进入高风险区 |
| 载荷层 | 目标特征、任务优先级、剩余能量 | 低成本精确打击、压制、诱导、封控 | 让单次暴露产生可重复的战果 | 若末制导与目标特征不匹配，则只保留侦察/诱导用途 |
| 感知层 | 雷达、光电、被动侦收、外部指示 | 目标确认、航迹更新、威胁分级 | 解决弱网条件下“看不全、传不稳”的问题 | 若外部指示中断，转为局部被动搜索与短窗接战 |
| 火控层 | 目标航迹、交战规则、授权等级 | 发射时序、补击顺序、毁伤分配 | 解决多目标并发时的火力分配摩擦 | 若授权链条过长，立即降级为预置规则 |
| 通信与任务软件 | 低带宽链路、异构协议、任务包 | 网关转译、边缘协同、任务重规划 | 解决跨密域、跨平台、跨频段协同难题 | 若链路被压制，保留本地自治和最小回传 |
| 保障与测试 | 演训数据、接口标准、试验场景 | 可靠性评估、边界修正、补给节奏 | 让低成本系统能批量形成战斗力 | 若无法完成接口联试，不进入批产节奏 |

这套方案的关键不是把每个节点都做成“全能平台”，而是把能力分布到网关、任务网络和边缘节点上：前沿节点负责把敌方暴露出来，边缘节点负责把数据变成可打击目标，火力节点负责在短时间窗内完成命中，评估节点负责把一次战果转成下一轮分配。其验证重点也应放在降级运行上，即在低带宽、数据不完备、局部节点失效时，仍能否保持最低限度的任务续接；一旦这条线闭合，低成本无人协同与精确火力才算真正进入可装备状态。
