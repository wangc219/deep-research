# 一、需求分析

## （一）需求概述

从未来任务中的真实断点起笔：何种对手行动、环境变化、时间窗口或体系约束使现有手段不能闭合任务，拟议装备能力将改变哪一个结果。内容随 Query 变化，不预设每份报告都要讨论相同的威胁维度、成本维度或体系口号。

## （二）国内外现状

只比较与本项目任务和装备机理直接相关的公开案例、技术基础和能力差距。比较应解释现有方案为什么仍不能解决所述任务，而不是罗列国家、型号和技术名词。国外与中国材料的证据粒度不同，应分别陈述，不用对称句式强行补齐。

## （三）建设必要性分析

围绕既定四个小标题分别回答不同决策问题。把必要性落到具体任务结果、能力缺口、领域机会和综合代价上；同一判断只出现一次。不同装备若解决不同断点，应分别说明，不用统一的“提升能力、填补空白、效益显著”段落轮换名称。

# 二、项目画像

## （一）装备图像概述

使用一张 Markdown 表格，表头固定为“武器装备|核心技术|形成能力|作战概念与主要效果”，每件已确认装备占一行。四列分别形成因果关系：核心技术必须能解释形成能力，形成能力必须能支撑最后一列中的实际部署、关键动作、作用对象和直接结果。最后一列不得为空，也不得写成可套给所有装备的抽象概念。重新综合底稿，不逐字搬运卡片，不在表后逐行复述。

## （二）作战运用模式

按装备真实的进入条件、关键动作、任务状态变化和退出或中止条件组织。流程长短与先后关系由装备机理决定；只保留会改变任务结果的步骤。链路闭环分析应指出本装备真正依赖的证据、授权、火控、效应或反馈关系，以及其中断后的具体后果，不套统一任务链。

## （三）体系贡献率分析

从项目实际基线出发，解释每件装备新增了什么原有手段无法替代的任务贡献，这一贡献通过什么机制传导到体系结果，在什么条件下衰减或消失。比较轴由装备差异和任务结果决定，可分别采用时间、覆盖、资源消耗、任务完成、压制持续性、拦截或毁伤等不同口径，不要求所有装备共享同一组维度。没有校准数据时给出变量、方向和验证思路，不编造贡献率点值。

## （四）主要战技指标

从每件装备的制胜机理和最可能失败的环节反推指标。指标应回答“测量什么才能判断该装备是否真正形成预期能力”，而不是展示通用性能清单。指标数量、量纲、工况、阈值表达和验证方式随装备实际情况确定；只有证据充分时给出区间或点值。不同武器不得复制同一指标组、同一试验路径或同一判退句。

# 三、总体方案

总体方案从逐装备因果链反推。总体架构只上提确实需要跨装备共享的任务状态、接口或资源关系，并说明这些关系为何影响作战结果。子系统方案保留装备本体的独有构型、效应主体、控制机理、输入输出、工程边界和集成难点。使用正式 Markdown 表格时，列项由本项目需要比较的关系决定；不适用的列不要设立，不用占位句填表。

# 四、关键技术

从装备形成预期战果的因果链中识别真正的技术断点。技术数量、层级和论证顺序由实际瓶颈决定，可围绕一项决定性技术深入，也可比较多项耦合技术。表格应让读者看清技术作用于哪件装备和哪个关键环节、受何种物理或工程约束、现有基础支持到哪里、需要解决什么问题以及什么证据能证明突破有效。不得按预设技术类别穷举，也不得让所有装备复用相同瓶颈、攻关路径或验证句。

# 五、研制基础
