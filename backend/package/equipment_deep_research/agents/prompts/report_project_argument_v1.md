## 写作起点

先理解 Query、query_analysis、逐装备事实底稿和公开证据，再写正文。对每件武器先在内部建立一条独立因果链：它在什么任务场景和约束下使用，作用于什么对象，执行什么关键动作，依靠什么机理形成什么直接结果，相对现有基线改变了什么，以及何时失效、证据支持到哪里。该因果链用于思考和核对归属，不作为固定字段逐项输出。

装备范围以 S6 最终入选的武器装备及其明确的配套能力为准。S6 未入选、仅在前序环节出现、只具一般支撑作用或与 Query 没有直接因果关系的装备，不得在正文中被扩写成新的项目主体。每一章都要回扣同一份 S6 入选清单：需求分析说明为什么需要它，项目画像说明它如何发挥作用，总体方案、关键技术和研制基础说明如何把它做成；不得在不同章节擅自增删、改名或替换入选装备。若 S6 只支持装备类别而不支持具体型号，正文保持类别级表述，不补造型号。

装备之间的因果链不同，正文组织也应不同。模型根据实际材料决定先写哪一项、展开到什么深度、采用段落还是表格以及哪些关系可以合并比较。不得让所有装备使用相同的开头、字段顺序、论证骨架、指标组合、验证流程或结尾句。删除装备名称后仍可原样换给另一件武器的内容必须重写。

正文以军事和研制决策价值为尺度。背景、趋势、体系口号、方法论解释和同义复述只有在能解释装备选择、技术取舍或失效边界时才保留。证据只能支持类别、演示、推断或待测变量时，应准确说明支持范围；不得补造型号、参数、成熟度、单位归属或试验结论。

正文聚焦军事需求场景、装备能力提升、新技术如何进入武器与任务链、新场景如何被装备能力打开。优先使用中文直述，少用英文缩写和生僻词，首次出现写明中文含义；确需保留缩写时首次出现写明中文全称，后续优先使用中文简称。正式来源标题、型号、证据编号和网址可保留原文；删除方法论解释、泛化体系口号、同义复述。

篇幅只是最低深度参照，不是字符上限。绝不得为了压缩而删去具体装备事实、来源映射、反证、验证边界或项目落地建议。达到本章的决策问题和证据边界已经闭合时自然收束，不为字数重复论证。

# 一、需求分析

## （一）需求概述

从未来任务中的真实断点起笔：何种对手行动、环境变化、时间窗口或体系约束使现有手段不能闭合任务，拟议装备能力将改变哪一个结果。内容随 Query 变化，不预设每份报告都要讨论相同的威胁维度、成本维度或体系口号。既定四级标题分工如下：

1. 背景分析：交代 Query 所指战场与任务背景下的对手行动、环境约束和任务链压力。
2. 需求阐述：严格从 Query 角度分析相关装备需求——需要什么装备能力/形态、为何需要、现有能力缺口在哪里；不提前展开具体型号方案、作战流程或工程验证。
3. 项目画像：聚焦围绕该装备（族）研发的作用与价值，说明其应对何种态势威胁、改变何种交战关系、形成何种作战前景与制胜增量；不提前写成第二章的详细作战运用或指标体系。

## （二）国内外现状

本节必须围绕 S6 入选装备回答“外部发展到哪里、国内已有基础是什么、差距为何构成新质装备建设需求”，固定使用以下三个四级小节，顺序不得改变：

#### 1. 国外情况

聚焦美国及其他美西方国家与 S6 入选装备直接对应的类似武器装备、公开试验/部署动向、作战概念变化和能力演进。每件入选装备只选少量最能改变判断的高价值案例，优先写官方文件、军方公告、预算/采购信息、试验演示和权威研究中的明确事实；不要把公开网页、新闻标题、型号清单或泛泛技术综述堆成资料汇编。每个案例至少回答“发展了什么、服务什么任务、相对旧范式改变了什么、目前处于何种可确认状态、对本项目形成什么启示”，无法确认的部署状态、性能和成熟度要明确标为推断或待核验。美西方国家不要求平均分配篇幅，按与本项目装备的相关性和证据质量取舍。

#### 2. 国内现状（中国）

聚焦中国与 S6 入选装备相对应的现役/在研装备基础、公开试验或应用迹象、可继承的技术与工业条件，以及仍未闭合的任务缺口。必须按入选装备逐项建立“已有基础—已解决问题—尚存短板—后续新质装备需求”的对应关系；证据只到类别、系列或能力方向时，不虚构具体型号、性能点值、装备状态或单位分工。国内现状不是泛泛介绍国防工业成就，也不是把国外案例换成中国名称，而是要明确哪些能力可以继承、哪些关键环节仍需新研、为何需要发展 S6 所选的新质装备。

#### 3. 对比小结

不重复前两节的资料，按 S6 入选装备和任务结果选择少量真正有判别力的比较轴，例如发现与定位、持续存在、突防/抗扰、闭环响应、效应可靠性、体系接入、规模与成本、降级可用性或工程成熟度。先指出国内外在这些轴上的可证据差距，再说明差距如何传导为任务链断点、作战关系劣势或建设风险，最后逐项落到“为什么必须发展哪一种新质装备能力、优先补哪一段链路”。对比只写能够由证据支持的差异；没有可比数据时使用定性判断并说明待验证变量，不以“总体先进/存在差距”等空泛结论收尾。该小节是建设必要性的证据前置，不得把“发展必要”写成脱离差距的口号。

## （三）建设必要性分析

围绕既定四个小标题分别回答不同决策问题。把必要性落到具体任务结果、能力缺口、领域机会和综合代价上；同一判断只出现一次。不同装备若解决不同断点，应分别说明，不用统一的“提升能力、填补空白、效益显著”段落轮换名称。

# 二、项目画像

## （一）装备图像概述

使用一张 Markdown 表格，表头固定为“武器装备|核心技术|形成能力|作战概念与主要效果”，每件已确认装备占一行。四列分别形成因果关系：核心技术必须能解释形成能力，形成能力必须能支撑最后一列中的实际部署、关键动作、作用对象和直接结果。最后一列不得为空，也不得写成可套给所有装备的抽象概念。重新综合底稿，不逐字搬运卡片，不在表后逐行复述。

## （二）作战运用模式

按装备真实的进入条件、关键动作、任务状态变化和退出或中止条件组织。流程长短与先后关系由装备机理决定；只保留会改变任务结果的步骤。链路闭环分析应指出本装备真正依赖的证据、授权、火控、效应或反馈关系，以及其中断后的具体后果，不套统一任务链。

## （三）体系贡献率分析

从项目实际基线出发，解释每件装备新增了什么原有手段无法替代的任务贡献，这一贡献通过什么机制传导到体系结果，在什么条件下衰减或消失。比较轴由装备差异和任务结果决定，可分别采用时间、覆盖、资源消耗、任务完成、压制持续性、拦截或毁伤等不同口径，不要求所有装备共享同一组维度。没有校准数据时给出变量、方向和验证思路，不编造贡献率点值。

## （四）主要战技指标

从每件装备的制胜机理和最可能失败的环节反推指标。指标应回答“测量什么才能判断该装备是否真正形成预期能力”，而不是展示通用性能清单。指标数量、量纲、工况、阈值表达和验证方式随装备实际情况确定；只有证据充分时给出区间或点值。不同武器不得复制同一指标组、同一试验路径或同一判退句。

# 三、总体方案

总体方案只能围绕 S6 最终入选的武器装备展开，不能退化为与装备无关的通用体系架构。先逐件回收 S6 入选装备的任务断点、作用对象、关键动作、效应机理和主要失效边界，再反推方案：每项架构、子系统、接口、软件、数据流和保障条件都必须能回答“服务哪件入选装备、支撑哪一个关键动作、改变什么任务结果”。

总体架构只上提多件入选装备确实共享、且会影响作战结果的任务状态、权限、资源或接口关系；若关系只属于单件装备，必须留在该装备的子系统方案中。架构中应明确入选装备之间的分工、交接条件、时序或资源约束，以及接口失效会造成的具体后果，不得用“统一指挥、协同作战、体系融合”等口号替代关系说明。

子系统方案必须按 S6 入选装备逐项落位。对每件装备分别说明决定其成立的产品形态/效应主体、感知或输入、控制与决策机理、输出与作用对象、外部接口、工程边界、集成难点和必要验证；不适用的内容不设栏，不得以公共子系统或空泛模块代替装备本体。正式 Markdown 表格的每一行应能明确对应一件 S6 入选装备，列项由装备差异和研制决策需要决定；表格后只作综合判断，不把同一段通用方案轮换装备名称。若某项设计事实不是 S6 或证据明确支持的内容，写成待定的设计选项或待验证变量，不伪装成已定方案。

# 四、关键技术

从装备形成预期战果的因果链中识别真正的技术断点。技术数量、层级和论证顺序由实际瓶颈决定，可围绕一项决定性技术深入，也可比较多项耦合技术。表格应让读者看清技术作用于哪件装备和哪个关键环节、受何种物理或工程约束、现有基础支持到哪里、需要解决什么问题以及什么证据能证明突破有效。不得按预设技术类别穷举，也不得让所有装备复用相同瓶颈、攻关路径或验证句。

# 五、研制基础

围绕“哪些基础能被具体装备继承，哪些缺口仍决定可研性”形成判断。

参与单位聚焦与本项目装备研发大致相关的承研/配套力量：从真实产品责任、关键技术接口、试验责任和证据交付反推；公开依据不足时只写能够成立的机构类型（总体设计院所、军工集团/主机厂、电子信息与材料企业、试验鉴定机构、高校科研院所等）或明确缺少归属证据，不虚构具体单位名称与承担关系。

技术基础聚焦已经比较成熟、可支撑新质装备研发的技术与工程能力：按装备区分可继承的成熟基础、新增工作、试验或供应链条件和当前可研结论，重点回答“现有基础是否足以支撑研发该新质装备”；不复制通用承研分工，不用统一占位句填表。
