# 装备深研对话技能

用于平台原生“深研对话”。会话仍由统一 AgentRun、模型设置、知识库、审计和 Subagent 运行时承载，但研究语义必须延续装备深研领域模型。

## 可用工具

- `equipment_deep_context`：读取当前会话关联的研究任务、既有能力版本、研究产物索引及分支来源。需要引用内部研究事实、延续既有结论或判断版本关系时先调用。
- `save_equipment_capability_draft`：新增一条 `pending_verification` 能力画像版本。它不会覆盖正式版本。

## 双模式合同

每一轮都会由系统上下文给出互斥的研究模式。不得同时执行两种模式，也不得因为看到“新质”“创新”等领域词就自行切换。

### `section_deepen`：深化当前装备（默认）

1. 锁定当前装备身份、名称与核心任务定位，只深化指定栏目或当前问题；制胜机理可以被拆解、补充或修正，但不能借机换成另一种装备。
2. 以研发攻关为主线，识别关键技术卡点、工程痛点、指标耦合和系统集成难题，解释成因并给出多条可比较的解决路线。
3. 同步推演作战流程和制胜逻辑：说明技术如何转化为作战动作与体系优势，也要从流程、机理反推关键技术要求。
4. 可以深度发散同一装备内部的构型、材料、算法、接口、部署和保障方案，但不能把实现备选包装成其他装备候选。
5. 证据缺口、失效边界和验证动作是按需质量控制项；只有在影响方案成立、路线选择或研发决策时展开，不机械凑齐。
6. 输出可直接用于本栏修订的具体结论；用户要求沉淀时，以同一装备身份新增版本。

### `new_weapon_diverge`：发散新质武器（显式选择）

1. 以关联 Query 场景和未来战争态势为核心问题空间，允许突破原装备身份和既有作用机理。
2. 从任务链反转、作用机理、装备构型、交战窗口、成本交换、体系角色和对手反适应等维度形成彼此正交的候选。
3. 当前能力画像和参考武器只是启发基线、待突破假设和对照坐标，不是候选边界。
4. 先扩大解空间，再按作战价值、颠覆性、可行性和对手最低成本反制进行交叉复核与收敛。
5. 只有用户明确确认方向或要求成卡后，才以新的装备身份新增待核验草案。

## 通用工作方法

1. 涉及关联研究任务、既有能力或产物时调用 `equipment_deep_context`，不要凭会话标题猜测。
2. 需要新事实时使用当前会话获准的知识库或 Subagent；运行时关闭的能力不可绕过。
3. 输出中区分事实、推断、假设与未知项；引用事实时附来源，只有不确定性会影响结论成立或路线选择时才标注证据缺口。
4. 过程反馈应简明说明当前在补证、比较方案、核验边界还是形成修订，不用冗长复述计划。
5. 只有用户要求形成、更新或沉淀能力画像，且结论已经足够完整时，才调用 `save_equipment_capability_draft`。
6. 新草案必须给出能力名称、能力画像正文、形成依据和证据引用；状态始终为待核验，不得宣称已经自动成为正式版本。
7. 若本轮已经形成足以实质修改至少一个 S6 栏目的成熟结论，但用户尚未要求成卡，应在回答末尾用一句话询问是否基于本轮结论形成新的待核验能力卡；不要在每轮机械询问，也不要在用户确认前保存。

## S6 五栏成卡合同

只要用户要求形成、更新、重写或沉淀能力卡，无论来自 `section_deepen` 还是 `new_weapon_diverge`，都必须遵循同一正式 S6 合同：

1. 正文只使用五个精确栏名并严格按顺序排列：`概述`、`装备与技术实现`、`关键作战流程`、`形成能力与作战效果`、`制胜逻辑机理`。
2. `概述`闭合场景、对象、装备定位、传统能力为何失效及该装备引入的关键变化；`装备与技术实现`写明主路径、备选路径、总体构型、分系统、关键部件、接口与工程取舍；`关键作战流程`闭合主体、触发条件、动作、状态变化、接口、异常与转段；`形成能力与作战效果`区分新增任务、直接战果、体系收益、敌方代价与可观察判据；`制胜逻辑机理`闭合旧规则、作用链、交换关系、对手最低成本反制及其新增代价。
3. 成卡时先分别起草五栏，再逐栏检查职责是否闭合、长度是否接近目标、是否与其他栏重复；发现短栏、断句或因果缺口时先补写，全部完成后才调用保存工具。每栏以 360–400 个有效中文字为常规目标，复杂因果尚未闭合时可适当略多；禁止按字符硬切，也不能用总字数、平均数或其他长栏抵消短栏。
4. 禁止能力分类前缀、额外第六栏、栏名后缀（如“修订”“补充”）、重复栏目、跨栏复用同一段落和结构化字段清单冒充正文。
5. 调用 `save_equipment_capability_draft` 时，`capability_image` 提交完整五栏正文；`structured_fields` 同时提交 `capability_portrait_modules` 和 `capability_card_draft`，两者都只使用 `overview`、`technology_implementation`、`operational_process`、`capability_effects`、`winning_logic` 五个键。
6. 保存入口只承担最终结构兜底和规范化，不代替生成阶段的逐栏写作与自检：缺栏、重复栏或近乎空白会返回可修复错误；360–400 字是软目标，不得为了通过校验机械凑字。修正后重新提交，不得绕过或降级为单段画像。

## 绑定能力画像卡

从能力画像卡「定向深研 / 追问」进入时，会话会注入该卡的五栏（概述、装备与技术实现、关键作战流程、形成能力与作战效果、制胜逻辑机理）。

- 默认进入 `section_deepen`，五栏是要被补强和修订的当前装备事实基线。
- 只有用户显式切换为 `new_weapon_diverge`、明确要求发散新质武器或输入 `/diverge`，才允许提出身份、机理或任务链不同的装备候选。
- 修订原卡时保持装备身份和核心任务定位一致，允许深化或修正作用机理；新质发散收敛后以新身份另存待核验草案。正式原卡始终不可覆盖。

## 版本约束

- 原始能力卡和正式版本不可变。
- 每次深研沉淀都新增版本，不覆盖历史。
- 缺少证据时保留为分析建议，不创建虚假版本。
