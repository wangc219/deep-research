# 公众号文章模块

从 `reference/wechat-mp-tools-2.3.3` 复制的微信公众号子项目，保留 MIT LICENSE 和 `UPSTREAM.json` 中的原始文件 SHA-256。参考目录无需在运行时存在。

保留原版账号池/扫码登录、公众号管理、分页与关键词查询、选中文章/时间范围/URL 批量下载、任务取消与进度、下载历史/预览、HTML/Markdown/PDF 与媒体资源、清洗规则和存量重清洗、RSS 定时同步/全文摘要/ETag、代理池与设置。仅迁入公众号依赖闭包，不含视频号、抖音、快手、小红书、B站、转码、自动更新和桌面壳。

平台适配：`platform_worker.py` 通过每用户 Unix socket 运行原版 Flask；FastAPI `/api/wechat-mp` 网关每次验证用户与知识库权限。所有 cookie、账号池、下载、RSS 与运行状态隔离到 `outputs/wechat-mp/<SHA256(uid)>`。跨 API worker 文件锁保证同一用户只有一个下载/RSS 进程；重启恢复已初始化空间。API 容器需单实例或对该持久化目录采取单实例归属，不能多副本共享写同一用户目录。进程随 API 容器停止，不随页面关闭停止。

浏览器入口：`/extensions?tool=wechat-articles`，与视频号转 DOCX 并列。内嵌原版七个页面；文件目录改为网页目录和 ZIP 下载。RSS 链接包含专用可撤销 token；RSS 不使用平台登录 token。复制订阅链接前先在原版界面初始化账号和内容。

镜像通过 `docker/api.Dockerfile` 安装隔离 Python 环境及 Chromium。源码开发可设 `WECHAT_MP_PYTHON` 指向安装了 requirements-mp.txt 的 Python。可配置 `WECHAT_MP_DATA_ROOT`（持久化数据）、`WECHAT_MP_SOURCE`（子项目路径）、`WECHAT_MP_SOCKET_ROOT`（短路径 Unix socket）。默认平台输出目录已由 compose 持久化。

原项目依赖微信读书授权/第三方中转及微信平台可用性。真实登录需要用户扫码；网络或账号限制由原版错误与验证码流程呈现。登录凭据和业务数据没有从参考项目复制。

视觉保留原版七页结构，配色、字体与边框继承平台主题变量；图标使用平台同款 Lucide，支持深浅主题和窄屏横向菜单。PC 微信自动刷新脚本作为原版兼容依赖保留，但原脚本不支持 Linux 桌面自动化；容器中的主要登录方式是网页扫码。

验收覆盖原版 27 项测试、平台真实 HTTP 鉴权/用户隔离/文件与 RSS 流程、浏览器主题与响应式布局，以及实际 Chromium PDF 导出。真实微信登录和在线文章采集须在用户扫码授权后验证。

公众号下载成果现在自动复制到个人沙盒共享 Workspace 的 `/采集成果/公众号文章/`；同级视频号成果位于 `/采集成果/视频号文字稿/`。浏览器“沙盒成果与入库”支持选择至多 100 项打包下载、打开个人空间预览及选择目标知识库入库。公众号源目录仍保存原始下载；工作区副本的编辑不会被无变化的刷新覆盖。页面关闭后后台每 10 秒检查已完成下载，失败记录可在成果页查看并重试。每个成果文件不超过 100 MB，单批 ZIP 总量不超过 500 MB。

成果清单由平台保存在 `outputs/collection-artifacts/<用户摘要>/`，文件访问与个人空间共用 no-follow 边界。下载、转录本身继续使用原运行环境；入库只有在用户选定目标知识库后才提交标准解析及索引任务。
