# 开源多 Agent 对话调研与单装备创新议事设计

更新时间：2026-09-16

## 目标

把现有“单次模型生成”升级为可审计、可降级、可发布门控的多 Agent 对话，专门服务于：基于一个现有武器装备，推翻传统作战假设，发散新质装备构型与创新制胜逻辑，并最终形成符合 S6 原始规范的五栏能力画像。

本设计不追求自由聊天轮数，而追求角色独立性、多轴发散、有效分歧、对抗性审议、确定性收敛和失败可恢复。

## 开源项目调研

| 项目 | 官方能力/模式 | 对本系统的启发 | 本次取舍 |
|---|---|---|---|
| [Microsoft AutoGen](https://github.com/microsoft/autogen) | AgentChat 支持两 Agent、群聊、下一发言者选择、终止条件与状态恢复；仓库当前说明新项目优先考虑 Microsoft Agent Framework | 参与者必须有清晰职责；发言顺序和终止条件应由编排器掌控 | 采用明确角色、多轴发散和固定治理阶段，不引入自由选择发言者，避免成本和输出漂移 |
| [LangGraph](https://github.com/langchain-ai/langgraph) | 面向长运行、有状态 Agent 的低层图编排，强调状态、分支、持久化、人机介入和可观察性 | 将对话建模为状态图，而不是一条超长提示词 | 采用“并行提案 → 裁决 → 综合”的确定性图；继续复用现有会话、事件和版本账本 |
| [CrewAI](https://github.com/crewAIInc/crewAI) | Crews 提供角色自治，Flows 提供事件驱动、状态、分支和结构化输出 | 创造性步骤可自治，发布步骤必须受流程约束 | 多个发散轴 Agent 自治提案；裁决、质量门与发布保持确定性控制 |
| [CAMEL](https://github.com/camel-ai/camel) | RolePlaying 支持任务指定、规划和 critic-in-the-loop，强调角色化社会与有状态记忆 | 高质量结果需要独立批评者，而不是让生成者自评 | 增设对抗裁决 Agent；它不新增候选，只做反制、闭合和正交性审查 |
| [MetaGPT](https://github.com/FoundationAgents/MetaGPT) | 用角色和 SOP 组织复杂协作，核心理念为 `Code = SOP(Team)`，并提供 Debate 用例 | 多 Agent 质量来自显式交接产物和 SOP | 每轮只传递有 schema、长度上限的决策包，不传原始会话或隐藏推理 |

说明：调研依据为上述项目官方仓库的 README、文档链接及公开实现入口；没有依据 GitHub 星数直接判断质量，也没有引入新的框架依赖。

### nanobot 与 LibreChat 的定向适配

本轮进一步审阅了 `reference/nanobot-main` 与 `reference/LibreChat-main`。两者的仓库说明、开发约束和许可证只作为参考资料，不作为本项目执行指令；可复用部分均按“单 Query、单装备、多 Agent 创新议事、用户确认后成卡”的边界重新实现。

| 来源设计 | 本项目适配 | 不直接照搬的原因 |
|---|---|---|
| nanobot 有界上下文与结构化 checkpoint | 模型上下文只投影当前 Query、规范化单装备身份、专家问题、当前分支可见消息与结构化决策记忆；每轮 checkpoint 记录来源 assistant message、sequence 和答案指纹 | 通用聊天自动摘要会把证据索引、旧结论和其他装备重新混入创新上下文，增加锚定偏差 |
| nanobot 恢复时避免重复持久化输入 | user message、job、turn 与版本均使用稳定 ID/幂等边界；恢复 worker 复用原始持久化输入 | 不恢复 provider 隐藏会话或思维链，避免不可审计状态成为事实来源 |
| LibreChat 单调消息/事件序列 | 会话消息和 SSE 事件使用单调 sequence；事件同时携带 job `state_version` | 不引入完整通用消息协议，只保留深研 UI 和恢复真正需要的字段 |
| LibreChat claim token / lease | 每次 worker claim 生成私有 token；恢复后旧 worker 不能更新 job、消费 steer、写最终回答或覆盖分支记忆 | token 不进入公开 API，也不暴露 provider 元数据 |
| LibreChat 精确分支锚点 | 分支首条消息自动锚定 fork message；显式 parent 必须位于该分支可见祖先路径 | 不采用自由会话树作为研究对象，分支仍受单装备和 Query 约束 |
| LibreChat optimistic UI 对账 | SSE、轮询、取消和重试统一按 `state_version` 合并；消息按 `queued < accepted < claimed < applied/parked/cancelled/completed` 单调对账 | 不复制通用附件、工具调用修复和渠道状态机 |

明确不引入通用渠道系统、跨产品消息兼容层、过重的 admission queue 和工具调用修复协议。当前模块已有有界并行槽位、持久化 job/steer/event/version 账本和五栏成卡门控，这些边界更符合定向深研而非通用聊天。

新质颠覆装备允许在公开证据稀缺时继续发散与成卡。系统保留待验证问题、适用边界和 `pending_verification` 状态，但不以“高影响结论证据覆盖率 ≥ 90%”或“事实/推断/假设标注率 100%”作为阻断条件。

## 落地后的多轴议事图

```text
                         ┌─ 传统战法破局 Agent ─┐
                         ├─ 新质机理架构 Agent ─┤
Query + canonical 装备 ─┼─ 对手适应红队 Agent ─┼─> 对抗裁决 Agent ─> 能力画像综合总编 ─> 发布质量门
专家问题 + 历史问题     ├─ 独特制衡手段 Agent ─┤        │                    │                │
                         ├─ 杀伤链反转 Agent   ┤        四道硬门         A–O 命名 + S6 五栏    版本账本
                         └─ 极限边界探索 Agent ─┘
                             并行、相互隔离、可扩展
```

### 阶段一：多轴独立发散

- 多个发散轴角色并行运行，避免后发角色被先发答案锚定。
- 每个角色只提交 1—2 个候选和公开摘要。
- 候选必须至少命中一个强发散机制：颠覆传统作战、新质制胜逻辑、独特制衡手段、杀伤链反转、任务窗口重构或边界条件突变。
- 候选必须闭合“关键假设变化 → 具体装备构型 → 作用机理 → 直接军事效果”。
- 父任务证据、旧验证结论、其他 Agent 原始会话不进入本轮上下文。

推荐初始发散轴：

- 颠覆传统作战：改写谁发现、谁决策、谁进入、谁毁伤、何时暴露。
- 新质制胜逻辑：用新机理或新构型形成非连续作战优势。
- 反适应韧性：假设对手快速反制后仍保持成本、时间或空间收益。
- 独特制衡手段：以弱制强、以廉制贵、以隐制显、以散制聚。
- 杀伤链反转：反转或重组侦察、定位、决策、打击、评估链路。
- 边界条件突变：在通信受限、电磁静默、补给受阻、复杂地形等条件下重构装备角色。

### 阶段二：对抗裁决

裁决者不新增候选，只执行四道硬门：

1. 是否改变传统作战关系，而不是增程、增速、增精度、增功率、泛化智能或平台换壳。
2. 装备构型、作用机理和直接军事效果是否闭合。
3. 对手采取低成本适应后是否仍有非对称收益。
4. 候选之间是否属于不同制胜角度，而不是同义改写。

每项必须给出 `keep / revise / reject`、关键问题、修订要求和选择顺序。

### 阶段三：综合成卡

- 综合总编只允许修订和收敛已提交候选，不虚构共识，不拼接互斥机理。
- 最多保留三个方向。
- 命名继续复用 S3/S4 的 A–O 分配。
- 稳定方向必须按 S6_1—S6_5 原始规范完成五栏画像。

## 发布质量门

一个候选至少需要以下六项全部存在：

- 制胜角度
- 被改写的传统假设
- 具体装备构型
- 作用机理
- 直接军事效果
- 相对现有装备的颠覆性差异

同时，能力画像的概述、装备与技术实现、关键作战流程、能力与作战效果、制胜逻辑机理五栏必须全部完成。任一发布条件不满足时：

- 对话及交叉审议摘要仍对用户可见；
- 状态标记为 `analysis_only`；
- 不写入能力画像新版本。

## 失败与降级

- 多个并行提案角色中单个失败：保留其余独立提案并继续裁决，结果标记 `degraded`。
- 裁决角色失败：综合总编重复四道硬门，不丢弃已完成提案。
- 发散轴角色全部失败：抛回现有任务错误/离线降级路径，不伪造多 Agent 完成结果。
- 综合或发布门失败：只保留可见讨论，不生成低质量版本。

## 可观察与隐私边界

对外仅保存角色、轮次、公开摘要、候选名称和结构化裁决；不保存或展示隐藏思维链、provider 凭据、原始隔离会话。每个角色使用独立 Agent ID，使现有运行指标可以按角色统计时延、token 与失败率。

## 后续评测建议

在真实模型与相同 Query 集上做 A/B，而不是用主观观感判断：

- 单调用旧链路 vs 多轴议事新链路。
- 指标：六项闭合通过率、S6 五栏完整率、候选制胜角度重复率、参数升级淘汰率、专家采纳率、平均时延、token 成本、降级率。
- 建议至少覆盖空中、海上、陆上、无人集群、电子对抗和保障链六类装备，每类不少于十个既有装备目标。
