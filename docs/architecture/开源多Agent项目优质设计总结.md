# 开源多 Agent 对话项目优质设计总结

更新时间：2026-09-14

## 背景目标

本总结面向“基于现有武器装备进行颠覆传统作战、新质创新制胜逻辑发散”的深研对话能力设计。参考项目包括 [AutoGen](https://github.com/microsoft/autogen)、[LangGraph](https://github.com/langchain-ai/langgraph)、[CrewAI](https://github.com/crewAIInc/crewAI)、[CAMEL](https://github.com/camel-ai/camel) 和 [MetaGPT](https://github.com/FoundationAgents/MetaGPT)。

核心目标不是简单增加对话轮数，而是让多 Agent 对话具备：

- 角色独立性：避免多个 Agent 被同一上下文锚定。
- 分歧有效性：不同角色必须从不同发散轴提出候选，覆盖颠覆传统作战、新质制胜逻辑和独特制衡手段等方向。
- 对抗审查：用独立裁决者筛掉参数升级、平台换壳和同义改写。
- 结构化收敛：最终回到 S3 A-O 命名和 S6 五栏能力画像。
- 版本可管理：深研后版本可以发布、标记、删除和恢复。

## 项目优质设计提炼

| 项目 | 优质设计 | 对本系统的启发 | 落地方式 |
|---|---|---|---|
| AutoGen | 多 Agent 对话、群聊编排、发言者选择、终止条件、状态恢复 | 多 Agent 不是简单并发调用，而要有明确角色、发言边界和退出规则 | 采用多轴独立发散、对抗裁决、综合成卡；由编排器控制阶段边界 |
| LangGraph | 用状态图组织长运行 Agent，支持分支、检查点、可观察和人机介入 | 深研流程应是可恢复的状态图，而不是一次超长 prompt | 将流程建模为确定性图：并行发散 -> 裁决 -> S6 综合 -> 发布门 |
| CrewAI | 区分自主协作的 Crews 与确定性控制的 Flows | 创造性环节可以自治，发布环节必须受流程约束 | 多个发散轴 Agent 自主提案；裁决、质量门和版本发布保持确定性 |
| CAMEL | 角色扮演、任务分解、critic-in-the-loop、角色社会模拟 | 高质量输出需要独立批评者，而不是生成者自评 | 增设“对抗裁决 Agent”，专门审查作战假设、机制闭合和对手适应 |
| MetaGPT | 用角色、SOP 和结构化交付物组织协作，强调 `Code = SOP(Team)` | 多 Agent 质量来自稳定交接产物，而不是自由聊天 | 每轮只传结构化摘要和候选包，不传隐藏推理或无边界上下文 |

```text
    |-- 对手适应红队 Agent
    |-- 独特制衡手段 Agent
    |-- 杀伤链反转 Agent
    |-- 极限边界探索 Agent
    v

    v
能力画像综合总编
    v
S3 A-O 命名 + S6 五栏画像 + 深研版本管理
```

## 对话质量提升的关键机制

1. 独立上下文隔离

每个提案 Agent 使用独立上下文和角色身份，避免“后一个 Agent 复述前一个 Agent”的锚定问题。输出只允许进入结构化摘要，不暴露原始长对话。

2. 多轴发散而非固定三路

自由群聊容易带来成本失控、结论漂移和责任不清。更适合本系统的是“多轴并行发散 -> 对抗裁决 -> 综合成卡”的确定性流程。发散轴可以继续扩展，但后续裁决、质量门和版本发布仍保持稳定治理。

当前推荐发散轴包括：

- 颠覆传统作战：推翻既有任务分工、进入方式、暴露时机和交战顺序。
- 新质制胜逻辑：从新物理效应、信息—能量—物质耦合和装备构型形成非连续机制。
- 反适应韧性：预设对手低成本反制后仍保持非对称收益。
- 独特制衡手段：以弱制强、以廉制贵、以隐制显、以散制聚。
- 杀伤链反转：重组侦察、定位、决策、打击、评估的先后关系。
- 边界条件突变：在通信受限、电磁静默、补给受阻、复杂地形等条件下重构装备角色。

3. 对抗裁决优先于自我反思

裁决者不新增候选，只审查四件事：

- 是否真正改变传统作战关系。
- 是否闭合“装备构型 -> 作用机理 -> 军事效果”。
- 对手低成本适应后是否仍有非对称收益。
- 多个候选是否属于不同制胜角度。

4. 创造性和发布治理分离

提案阶段鼓励发散，发布阶段必须满足质量门。未通过质量门的结果可以作为可见讨论保留，但不能写入正式能力画像版本。

5. SOP 化交接

每轮交接采用结构化字段，避免把长篇聊天历史直接塞给下一轮。这样能降低噪声，提高可审计性，也便于版本追踪和失败降级。

## 与本系统需求的映射

| 用户需求 | 设计响应 |
|---|---|
| 深研后命名参考 S3 A-O 格式 | 综合成卡阶段复用 S3/S4 的 A-O 命名分配 |
| 深研后五栏目按 S6 要求撰写 | 最终版本必须完成 S6_1-S6_5 五栏画像 |
| 增加深研后版本管理 | 深研结果进入版本账本，支持删除、恢复和发布门状态 |
| 提升对话功能质量 | 引入多轴独立发散、对抗裁决、结构化综合和质量门 |
| 输出预算提升到 12000 tokens | 最终综合/S6 成卡阶段保留更大输出空间 |

## 推荐质量门

候选能力至少需要具备以下要素，才允许发布为深研后版本：

- 制胜角度明确。
- 被改写的传统作战假设明确。
- 具体装备构型明确。
- 作用机理明确。
- 直接军事效果明确。
- 相对现有装备的颠覆性差异明确。
- S6 五栏全部完成。

## 结论

五个开源项目的共同启发是：多 Agent 的价值不在“更多角色聊天”，而在“角色隔离、发散轴设计、流程编排、批评机制、结构化交接和可治理发布”。因此，本系统更适合采用工程化议事流程，而不是开放式群聊。

最终推荐方案是：借鉴 AutoGen 的多角色对话边界、LangGraph 的状态图、CrewAI 的自治与流程分层、CAMEL 的 critic-in-the-loop、MetaGPT 的 SOP 化协作，形成面向单装备新质制胜逻辑发散的多轴深研议事机制。
