# 企业多用户与双工作台融合

企业管理入口为 `/enterprise`。组织页管理租户、部门父子关系和部门管理员；成员页复用平台成员管理；功能权限页设置租户、部门和用户的读取/写入规则；运行监控页每 15 秒刷新最近 24 小时请求趋势、错误数量、延迟与主机负载。

## 身份与个人数据

- 平台账户、JWT 和平台 API Key 是两个 API 入口的共同身份来源。`/api/v1` 的旧工作台接口和 `/api/equipment` 的平台接口都执行服务端授权。
- 融合前导入的研究任务、Query、能力画像、研究报告和深研对话作为全员只读历史数据；融合后产生的数据归属创建它们的普通用户并按 owner 隔离。`admin` 与 `superadmin` 均可全局读取、创建、修改和删除非只读业务资源，并且跨用户写操作进入操作审计；代管不会改变资源 owner。
- 旧研究任务使用持久化的 `tenant_id + workspace_id` 绑定平台租户与用户 UID；Query 与生成任务持久化 `owner_uid`；收藏使用私有 owner；深研对话继承个人研究任务的归属。平台新接口继续使用 PostgreSQL 的 `owner_uid`。
- 后台 Query 生成复制任务所有者，并在相同身份范围内检索既有 Query。相同内容和相同幂等键在不同用户之间互不冲突。
- 浏览器提交的角色、租户、工作空间和用户身份头会被移除并由服务端重建。报告下载、事件流、深研路径和请求体内的关联任务 ID 同样检查归属。
- 管理员和超级管理员可以查看和管理他人旧工作台深研对话。平台原生深研被代管时仍沿用资源所有者的 Conversation、知识权限和工作目录边界，审计记录真实管理员身份，避免因代管而改变资源归属或扩大模型运行时的数据范围。
- Query 和研究任务持久化知识范围：`null` 表示对资源所有者当前可见的全部知识库按需开放，显式 ID 列表表示范围上限，空列表表示禁用。Query 创建 Run 时继承该三态；每次实际检索仍与 owner 的实时授权取交集，不能把历史选择或超级管理员身份当作授权授予。
- 管理员或超级管理员在他人 Project 下新建研究任务、Query、Query 生成任务或原生深研会话时，资源归属取 Project 的真实 UID，而不是操作者 UID；分支、消息和能力草案继续继承该所有者。
- 受保护写接口先记录结构化 `attempt` 审计；PostgreSQL 个人资源在业务 owning transaction 内再记录 `success` 审计，包含 actor UID、资源类型、资源 ID、owner UID、动作及是否跨用户。审计写入失败会阻止同事务业务提交。
- 无所有者或带旧工作台导入标记的融合前记录向所有登录用户只读展示，不自动分配给首次登录或访问门户的用户。融合后记录继续使用真实 owner；新的个人同步使用 `workbench-user-sync`。
- 浏览器本地草稿和收藏展示偏好按用户 UID 分开；研究 SSE 使用认证请求头，令牌不会进入 URL。

## 授权与组织

功能权限优先级为：用户 > 当前部门 > 租户；没有规则时允许使用。写入必须同时允许读取。上级部门的规则不隐式覆盖子部门。管理员和超级管理员不受业务功能规则限制。普通用户的功能授权不会扩大个人研究数据的可见范围。

知识库和 Agent 的资源共享支持全局、租户、部门和指定用户，读取和管理分别配置。普通用户只有获得具体资源的显式管理授权才能修改；旧知识库全局共享的默认配置不会自动提升普通用户为管理员。

知识库补充分为公共知识库和个人知识库：管理员可创建公共或定向共享知识库；普通用户可自助创建仅本人可见的个人知识库并管理其中内容，但不能扩大或改写共享范围。管理员和超级管理员始终可以查看和管理全部知识库。列表、详情、上传、工作区导入、检索和图谱等入口统一由后端按资源权限判定，前端不再用“是否管理员”提前阻断个人知识库所有者或只读共享用户。

部门所属租户决定用户所属租户。父子部门必须属于同一租户，修改组织关系使用 PostgreSQL 事务锁并检查循环。已有成员的部门不能直接跨租户移动，带成员或子部门的非默认部门不能直接删除。租户、部门结构和权限变更写入操作审计。

## 模型与监控

统一在 `/models` 管理供应商、聊天模型和 API Key。嵌入工作台的真实研究与 Query 生成会绑定平台默认模型或指定的 `model_spec`；API 和 Worker 执行时读取平台模型缓存中的有效凭据。任务仅保存模型标识及非密钥配置。平台旧研究适配器使用 OpenAI Chat Completions 兼容协议；原生 Anthropic/Gemini 协议未在此次验收中验证。首次验收使用 fake 模式；后续真实模型调用验证见本文末节。

企业运行监控统计受保护 API 的 HTTP 请求，包括已认证但被功能权限拒绝的请求。它不是模型 token 或计费统计；模型/工具使用量沿用 `/dashboard`。SSE 耗时包含连接持续时间。资源指标描述 API 所在主机/容器可见的资源，不是每个租户的独占用量。未认证请求不计入某个租户。

## 注册、登录与注册用户隔离（2026-09-26）

系统初始化时只允许创建一个超级管理员；初始化完成后是否开放自助注册由 `EQUIPMENT_ALLOW_SELF_REGISTRATION` 控制。自助注册固定创建 `user` 角色并加入默认部门，客户端不能提交或注入管理员角色。注册成功直接建立登录会话，后续支持 UID 或唯一手机号登录；每个受保护请求都会重新读取用户状态，因此超级管理员修改角色或删除账号后，无需等待旧令牌过期即可立即生效。登录同时具备失败次数锁定和 IP/账号组合限速。

注册后的普通用户自动进入超级管理员的全局用户列表，超级管理员可查询、编辑、重置密码、调整部门和普通用户/管理员角色，或通过软删除停用账号。普通用户不能访问用户管理接口；普通管理员仅能管理本部门普通用户。

新增真实 HTTP 注册用户闭环验证：两个用户分别完成注册以及 UID/手机号登录，超级管理员可检索和修改两者；双方创建的研究任务、Query、深研对话和个人收藏互不可见，超级管理员可全局读取；停用其中一个账号后其旧令牌立即返回未授权，另一账号及数据保持正常。注册角色注入被拒绝，重复注册返回冲突。相关认证、权限和研究服务单测 43 项及该真实场景均通过。

## 管理员即时升降权（2026-09-26）

超级管理员可把普通用户提升为 `admin`，也可把管理员降回 `user`。角色存储在服务端用户记录中，每个受保护请求都会重新读取，不把 JWT 内的旧角色当作权限依据，因此同一个已签发令牌在下一次请求立即获得或失去全局业务权限。

`admin` 的全局业务权限覆盖研究任务及产物、Query 与生成任务、能力画像、研究报告、深研对话、收藏、Agent 以及公共和个人知识库。跨用户写入继续使用资源 owner 的 Project、Conversation、工作目录和知识检索边界，并记录真实操作者。`superadmin` 继续独占角色授予与撤销、超级管理员账号保护、用户跨部门调整、租户、部门结构和功能规则治理；普通管理员不能把自己或他人提升为超级管理员。

前端把 `admin` 与 `superadmin` 统一显示为全局业务视角，收藏等页面不再把管理员标成个人范围；成员编辑弹窗明确提示升降权边界。登录中的页面会低频重新同步服务端角色，检测到升权或降权后清空旧角色下的项目与研究缓存并重新加载，无需退出登录。

本轮验收包括后端权限、知识库、研究服务与认证定向单测 103 项，平台前端全量单测 454 项，旧工作台单测 92 项，完整前端 lint 与两个生产构建。部署后的真实 HTTP 场景分别验证管理员即时升降权、注册用户隔离、个人知识库隔离、超级管理员用户 CRUD 和超级管理员跨用户代管，五个场景均通过。

## 全局业务代管边界（2026-09-26 追加）

统一权限矩阵如下：

| 模块 | 普通用户 | `admin` / `superadmin` |
| --- | --- | --- |
| Project、普通对话、附件与产物 | 仅本人资源 | 全局读取和管理，可在目标用户 Project 下创建对话 |
| Agent Request、AgentRun、队列、运行事件流 | 仅本人对话及运行 | 全局读取、发起、取消和管理 |
| 定时任务 | 仅本人任务 | 全局读取、修改、立即运行和删除 |
| 研究任务、Query、报告、能力画像、深研、收藏 | 融合前历史数据全员只读；融合后仅本人数据 | 全局读取和管理，历史数据仍保持只读 |
| 公共及个人知识库 | 仅本人或获授权资源 | 全局读取和管理 |
| Dashboard 业务监控 | 不可访问 | 全局访问 |
| 用户角色、租户、部门、超级管理员账号及他人密钥 | 不可访问 | 仅 `superadmin` 可治理 |

所有管理员代管路径区分三个身份：`actor` 是实际发起操作并进入审计的管理员；`resource owner` 是 Project、Conversation、定时任务及其产物的持久化所有者；`execution user` 是运行 Agent、解析工作目录、选择知识库和创建后续资源时使用的身份，始终取 resource owner。跨用户操作不会把 owner 改成管理员，也不会让目标任务继承管理员的个人工作目录、知识授权或密钥。

Project 列表和对话导航在管理员全局视图显示 owner UID；为他人创建 Project 时必须显式提交目标 owner，普通用户提交他人 UID 会被拒绝。定时任务编辑器只允许选择同一 owner 的 Project，立即运行产生的 Conversation、Request 和 Run 均继续归属任务 owner。普通对话状态、上下文压缩、附件确认和 artifact 下载同样先解析 Conversation owner，再进入对应用户的工作目录。

用户首次进入装备深研且没有自己的可选 Project 时，系统以用户维度幂等创建并默认选中托管项目「武器装备深研」。管理员的全局项目列表不参与这一判断，并发进入不会为同一用户重复创建默认项目。

升权和降权不依赖重新登录：后端每次请求从数据库加载最新角色，前端同步角色后清空旧权限范围下的项目和研究缓存。升为 `admin` 的旧令牌下一请求即可获得上述全局业务能力；降回 `user` 后同一令牌下一请求恢复 owner-only，并对他人资源返回不存在，避免泄露资源是否存在。
