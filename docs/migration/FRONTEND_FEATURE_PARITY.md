# 装备研究前端统一验收矩阵

## 使用方式

本矩阵是 React 工作台逐路由迁移到 Vue 3 的放行清单。每个路由只有在功能、接口、视觉和自动化验证全部达到“可切换”后，才允许在 `web/src/router/index.js` 中替换 `EquipmentWorkbenchHost.vue`。未通过的 Vue 页面仅作为迁移草稿，不进入正式路由。

状态定义：

- **已覆盖**：Vue 正式路由已承担该能力并通过验证。
- **部分覆盖**：已有 Vue 实现或 API，但不满足完整功能/视觉基线。
- **未覆盖**：仍由 React 工作台承担。
- **受阻**：代码已具备验证条件，但依赖本地服务或浏览器环境恢复。

## 公共边界收口清单

| 边界 | 当前状态 | 放行要求 |
| --- | --- | --- |
| 认证与租户/项目作用域 | React 仍通过 `platformRequestHeaders` 自行拼装；Vue 使用平台 `base` API | 所有装备 API 只经 `web/src/apis` 发出；作用域头、401、错误清洗行为与平台一致 |
| API 命名空间 | React 使用 `/api/v1/*`，Vue 草稿页使用 `/api/equipment/*` 兼容接口 | 明确每项能力的权威接口；适配只存在于 API 层，页面不感知双命名空间 |
| 状态缓存 | 装备资源 Pinia Store 已建立，支持并发合并和账号代次隔离 | 写操作成功后按资源失效/刷新；任务详情、分页参数和活跃轮询纳入统一策略 |
| 实时状态 | 深研使用平台原生消息/SSE；任务详情草稿仍为全量轮询 | 任务事件使用认证 SSE 和恢复游标；隐藏页停更、断线退避、终态停止、迟到响应隔离均有测试 |
| 错误与幂等 | React 内有独立 `requestResult` 和 Idempotency-Key 逻辑 | Vue API 层保留服务端错误详情并统一生成/复用幂等键，页面只处理业务状态 |
| 跨框架通信 | 仅保留一个 React 挂载点；旧深研事件转发 Vue 路由；嵌入模式不挂载 React Dock | 每迁移一个路由就删除对应事件桥；最终无 React root 和全局装备事件 |

## 各路由最低验收用例

### 研究任务

1. 分页、搜索、状态筛选和刷新后选择保持正确。
2. 从已发布 Query 创建单个/批量任务，模型、知识库、Agent 和路线参数不丢失。
3. 创建、启动、停止、失败续跑、归档和永久删除遵守权限与幂等语义。
4. 刷新、断网重连、切换账号后，旧请求和旧 SSE 不得污染当前会话。
5. 桌面/移动端及浅色/深色主题与现有任务卡、抽屉和空/错/加载态一致。

### Query

1. 手工创建和模型生成均保留知识库范围与模型选择。
2. 生成任务可轮询、取消、删除；失败后可读错误且可重试。
3. 单条和批量发布/归档/删除结果与服务端一致，部分失败可定位。
4. “直接研究”和批量建任务能回到对应任务并保持 Query 上下文。

### 能力画像

1. 同一任务的正式卡、深研卡、版本链和差异关系准确，身份键不串卡。
2. 五栏内容、S5 分数、证据、参考武器、待核验状态完整展示。
3. 收藏、专家反馈、回滚/删除/恢复和深研合并后立即读取服务端终态。
4. 定向深研只打开 Vue 原生路由，返回能力画像时定位原卡且无旧浮层。
5. DOCX、PDF、打印布局内容与当前 React 输出一致。

### 报告

1. Reporter 运行中展示真实阶段，能力画像先于报告正文可见。
2. 正文到达后无闪屏替换，刷新或断线后可继续收敛。
3. Reporter 明确失败时展示原因、已完成能力画像和断点续跑入口。
4. Markdown、GFM 表格、装备表补齐、深研补充及打印/下载结果一致。

### 收藏

1. 全局/私有范围、分页、搜索和模块筛选组合正确。
2. 快照在原任务归档后仍可读；显示名和备注编辑以服务端结果为准。
3. 删除后相关能力卡同步取消收藏，跳转可定位原任务和原卡。

## 当前阶段结论

- 阶段 0 的功能/接口/视觉矩阵已建立；浏览器截图基线因本地服务未启动暂记为受阻。
- 阶段 1 的深研路由隔离和装备资源 Store 已完成；公共 API、认证、错误和实时任务边界仍需收口。
- 阶段 2 的 Vue 收藏页已通过验收并切换正式路由。
- 当前允许正式使用的原生 Vue 装备路由是深研对话和收藏；其余 Vue 页面不得提前替换 React 正式路由。
