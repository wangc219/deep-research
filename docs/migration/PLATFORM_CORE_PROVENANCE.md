# 平台内核来源与融合记录

本文仅用于许可证、版本和历史迁移审计，不是产品架构或对外品牌说明。

当前产品是「装备智能研究平台」。用户、权限、项目、对话、知识库、知识图谱、模型设置、任务调度和审计能力统一由 `backend/package/platform_core` 提供；装备研究能力由 `equipment_deep_research` 通过稳定应用端口接入。二者共享同一身份、数据和运行平面，是同一产品内的高内聚领域模块。

平台内核的早期实现吸收了 Yuxi v0.7.3（提交 `9b67368c6baeb731f89e1076da8a1b68ff52178a`，MIT）中的部分通用能力，随后完成了包名、运行入口、权限模型、数据模型和装备研究链路的统一。原 Python 包已规范化为 `platform_core`，发行名为 `platform-core`。

## 当前边界

- 运行时不依赖 `reference/Yuxi-main`，该目录只作为来源和许可证审计材料。
- HTTP/SSE 接入统一位于 `backend/server`，平台用例统一位于 `platform_core.services`。
- `equipment_deep_research` 通过平台端口使用身份、知识、模型、任务和交付能力，不建立第二套平台服务。
- 产品展示名、容器、状态目录和新部署资源统一使用 `deep-research` / `platform` 命名。
- `YUXI_*` 环境变量及少量持久化标识只作为旧部署的一次性兼容输入；新配置统一使用 `DEEP_RESEARCH_*`。
- 第三方著作权与 MIT 许可证全文见 `THIRD_PARTY_NOTICES.md`。

## 融合完成标准

1. 一个 Web 工作台和导航体系；
2. 一个身份、租户、部门和权限模型；
3. 一个模型目录与凭据管理入口；
4. 一个知识授权与检索端口；
5. 一个 Durable Task、事件与运行审计体系；
6. Query、研究、画像、深研与报告共享项目和运行血缘。

历史来源不会作为当前架构中的独立系统出现。任何新增功能都应直接落入平台内核或明确的领域模块，并遵循 [一体化架构](../ARCHITECTURE.md) 的依赖边界。
