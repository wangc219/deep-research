# 前端统一迁移计划（React 工作台 → Vue 3）

## 目标

在不改变后端业务语义、公开路由和现有视觉基线的前提下，把装备研究域统一到平台 Vue 3、Vue Router、Pinia 和 `web/src/apis` 技术栈，最终移除嵌入式 React 根节点、跨框架事件状态同步、React 运行时和 React Vite 插件。

迁移采用逐路由替换。当前全部 `/equipment/*` 正式路由已经切换到 Vue 3；旧 React 源码仅暂作为
像素级 CSS 与两个无框架纯函数的设计基线，不再创建 React root，也不进入生产运行时。

## 不变量

- 保持 `/equipment/*` 路由、查询参数和可分享链接兼容。
- 保持 `/api/equipment/*` 与现有 `/api/v1/*` 后端能力，不迁移数据库和任务执行器。
- 保持登录、企业隔离、权限校验、模型选择、知识库范围、SSE/轮询恢复语义。
- 保持现有页面信息层级、交互入口、浅色/深色主题、桌面与移动端布局。
- PostgreSQL 与后端终态仍是事实来源，不用前端乐观状态覆盖最终结果。

## 每阶段验证门禁

2. `pnpm run test:unit`
3. `pnpm run build`
4. 真实浏览器覆盖主路径、空态、加载态、失败态和返回导航
5. 涉及 UI 时核对桌面、移动端、浅色和深色主题
6. 涉及任务状态时验证刷新、断线恢复、终态与权限隔离

操作顺序：`dry-run` → 核对 owner/project → `import --artifact-root ...` → `validate`。失败批次会标为
`failed` 并保留错误；可修正环境后重放，已导入旧 ID 会安全跳过。

## 回退原则

- 路由是迁移和回退的最小单元，不在同一路由同时维护两套可见 UI。
- 新 Vue 页面未通过验收前，不删除对应 React 实现。
- 后端接口兼容层至少保留到所有 Vue 路由稳定后，再单独清理。
- 任何数据写操作必须继续由后端鉴权并返回最终状态。
