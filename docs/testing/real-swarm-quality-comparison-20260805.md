# `swarm_quality_v1` 与 `winning_swarm_dynamic_v2` 同 Query Real 对比

日期：2026-08-05  
Query：`西太高强度对抗中前沿机场受毁与强电磁压制下跨岛链无人远程火力持续释能装备研究`  
共同约束：real / Codex / `gpt-5.5` Reporter / 自动路线 / 专家交互 / 2 轮 / `project_argument_v1` / 显式 `combat_scenario`、`weapon_equipment`、`operational_employment`，系统补齐国际态势与跨域融合基线。

本轮要求先围绕 Query 发散，再收敛为 5—7 个可独立立项的具体武器装备。每项必须写明项目功能、敌方目标与反制、我方部署和交战流程、直接战果、失效边界和可证伪试验；通信、算法、网关、供应链和保障只能作为装备接口，不能替代主体装备。

## 1. 结论

修复后的 `winning_swarm_dynamic_v2` 更适合正式装备需求挖掘：L1—L3 三层门均通过，公开来源绑定率 1.0，最终 Audit 为 `approved`，5 项装备画像最大相似度仅 0.2473。它也证明动态候选账本能够从 Query 自主保留海上无人释能、岛岸无人发射、低成本弹药族和高功率微波等不同制胜关系，而没有机械覆盖用户给出的全部示例。

但原始 Dynamic 产物不能直接接受。自动 S6 把“标题枚举多个装备”和“画像高度重复”仅列为 warning，仍错误标记通过；5 项中第 2/5 项均为反辐射巡飞弹，第 1/3 项又继承了反辐射画像。首次报告因此只有形式上的 5 项。只有在本轮把卡数、具体标题和组合互异性升级为交付硬门、按结构化字段重建画像，并从候选账本补入高功率微波方向后，Dynamic 才达到正式状态。

`swarm_quality_v1` 明显更快，墙钟 576.738 秒，仅为 Dynamic 的 30.6%；最终 6 项也更丰富，最大画像相似度 0.4080。但其 L1—L3 门均未通过，2 张卡置信度低于 0.70，Claim—公开来源绑定率仅 0.8214，因此 Audit 仍为 `limited`。它适合作为快速、高多样性的候选装备初稿，不应在当前证据状态下当作正式发布结论。

## 3. 最终装备组合

### 3.1 `swarm_quality_v1`

1. 半潜预置巡航弹无人艇：在机场与固定岸基节点受毁后，以海上预置、受控释放和射后转移续接远火。
2. 无人值守岛岸巡航弹车：在道路和临时阵地短停展开，完成任务包装订、授权复核、发射和转移。
3. 失联复核远程巡航弹：在目标包过期、导航受扰和链路中断时，以末段独立复核约束毁伤或拒打。
4. 多模复核反辐射巡飞弹：跨越敌雷达关机窗口，排除诱饵辐射源并持续压制真实防空节点。
5. 诱扰开窗可消耗无人弹：用特征模拟、伴随干扰和短时中继诱导敌火控资源错配，为主攻弹药开窗。
6. 微波反蜂群巡飞弹：保护海上无人艇、岛岸发射车和补给节点，降低传统点防空对低慢小蜂群的成本压力。

该组合覆盖海、陆、远程弹药、SEAD、电子攻击和节点自防御六类关系，跨卡最大相似度为 0.4080，文本和机理区分良好。主要限制是证据直接性：公开资料可以证明相关装备族和技术方向，不能充分证明强电磁压制下的授权、效果确认、补射闭环及微波巡飞平台工程可行性。

### 3.2 `winning_swarm_dynamic_v2`

1. 低特征预置巡航弹无人艇：把受毁机场的单点释能转为大量低特征海上发射节点，迫使对手扩大广域搜剿。
2. 多模复核反辐射巡飞弹：把敌方持续电磁开机行为转化为可猎歼辐射目标，并为后续远火制造窗口。
3. 无人值守岛岸巡飞弹发射车：以无人值守短停发射、弹车分离和多阵位接替维持岛岸火力波次。
4. 模块化低成本巡航打击弹药族：以共用接口、冻结构型和可规模补充改变高价拦截弹与巡航效应器的交换关系。
5. 高功率微波巡飞压制弹：对雷达、通信、电子战和反无人传感节点实施短时功能压制，为后续弹药进入与补射开窗。

修复后 5 项均有显式 `project_function`、完整五模块画像、敌我行动、直接战果、失效边界和验证计划；跨卡最大相似度为 0.2473。第 5 项由未入选的高分挑战候选补位，置信度 0.68，明确保留为中低成熟度探索项：若靶场不能重复确认功能压制及恢复窗口，或窗口不能驱动后续交战决策，即淘汰主装备定位。

## 4. Query 发散是否被示例框死

两种模式都没有把示例目录机械映射为固定答案：

- “空中蜂群母舰/无人僚机”未进入最终主体装备，因为前沿机场受毁、空中加油受限和高带宽链路不可依赖时，它们只能提供窗口性诱骗、中继、电子压制或 BDA，不能承担持续释能主轴。
- “潜射/水下火力舱”被识别为高价值但低成熟度方向；公开证据更强地支持海上/水下无人系统的感知、保障和通道任务，尚不足以证明长期待机、远程授权、抗俘获和战时再装填闭环，因此最终收敛到可更早验证的半潜/水面无人巡航弹释放艇。
- 两种模式都自主收敛到海上无人释放、岛岸机动释放、反辐射开窗和低成本消耗四个共同矛盾，说明最终装备由 Query 的机场失能、强电磁压制和持续释能断点驱动，而不是由示例名词驱动。
- Quality 进一步保留了失联复核巡航弹、诱扰无人弹和反蜂群微波弹；Dynamic 则更强调模块化低成本弹药族及对敌电子节点的微波功能压制。两者差异来自候选组合逻辑，而非预设类别配额。

## 5. Dynamic 原始失败与修复

原始 S6 自动结果存在三类硬问题：

1. 第 1 项标题为“搭载封装式远程巡飞弹药或小型巡航弹发火力”，第 3 项为“车载或拖曳式无人巡飞弹药发射车火力”，均是枚举/句段而非可立项装备名。
2. 第 2 项“空射巡飞弹药”和第 5 项“射频复核巡飞弹药”实际都是同一反辐射巡飞压制弹，组合只有 4 个有效装备族。
3. 第 1、2、3、5 项画像两两相似度为 0.805—0.904，海上无人艇和岛岸发射车错误继承了“关机目标保持—末端复核—反辐射猎歼”流程。

原逻辑把这些问题当作非阻断 warning，`s6_quality_gate_passed=true`。首次报告质量分为 0.95，因跨章节长句复用失败，Audit 为 limited。随后独立 Reporter 重试又未保留 5 个项目名，质量门以“覆盖 0/5 个输入方向”和军事信息密度不足拒绝，且没有覆盖原报告。

本轮修复：

- 5—7 项卡数、枚举式标题、重复名称和机制高度重复改为 S6 交付硬门。
- S6 通过只保留装备名、顺序和结构化字段，不再信任模型写出的画像正文；每张画像始终按当前装备族合同重建。
- 完成态升级脚本可读取最终 `model_result`，修复标题、按装备族去重，并从候选账本选择未覆盖的高分具体装备补位。
- 新增无人水面巡航弹释放、岛岸巡飞弹发射车和高功率微波巡飞压制的画像识别，避免再次落入 PrSM、反辐射或固定定向能阵地合同。
- Reporter 刷新在卡数和顺序稳定时可按卡序替换旧别名和旧画像；同时明确“现役效能跃升—传统赛道跨代优势—新概念赛道”三轨建设取舍。

## 8. 推荐

1. 正式装备需求论证优先使用修复后的 `winning_swarm_dynamic_v2`，因为它能保留候选账本、对手反适应、专家修复、组合淘汰和可证伪边界，并最终形成公开来源可追溯的互异项目组合。
2. 快速探索或低预算初筛可使用 `swarm_quality_v1`；本轮它快约 69.4%，且装备多样性很好，但必须把阶段门、低置信度卡和来源绑定缺口显式带入人工评审。
3. Dynamic 后续优化应减少 17 个动态 Agent 中的同族重复候选，提前按装备族和独立验收变量去重；不能通过降低证据门、删除失败边界或放宽重复门换取速度。
4. Query 模板应继续坚持“示例只是思考维度、最终由任务链断点收敛”的写法，并把“具体项目功能、敌我行动、直接战果、失效边界、可证伪试验”作为所有模式共同硬合同。
