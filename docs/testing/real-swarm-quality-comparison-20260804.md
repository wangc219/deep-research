## 1. 最终结论

`winning_swarm_dynamic_v2` 是本 Query 下更适合装备论证的模式。它最终形成 6 个直接作战装备、6 个互异装备族，单一装备主体和场景闭环均为 100%，平均置信度 0.8666；`swarm_quality_v1` 虽然更快完成 Reporter-only 恢复，但最终画像中仍有 2 项把多个构型合并为装备族，另有 1 项概述没有实质写出敌方目标/反制，平均置信度仅 0.7367。

## 6. 本轮修复的根因与措施

1. **装备族短缺时 repair lane 不启动**：原逻辑只看通过数量，数量已满但装备族不足时不会补位。现按 `preferred_distinct - current_distinct` 分配最多缺失数量的并行 repair lane。
2. **repair 候选重复修已有装备族**：现优先选择通过集合中尚未覆盖的装备族，并按装备族去重。
3. **配套武器污染主装备分类**：分类器先读取标题与首个主装备形态，再读取配套武器；“反舰导弹与反辐射弹药成组使用”不再把反舰导弹误归为反辐射。
4. **PrSM/HIMARS 投影错误**：PrSM 归为地射远程精确制导导弹，HIMARS/M270 仅作为发射接口；升级标题保留装备对象和直接作战增益。
5. **S6 失败后无法恢复**：`S6QualityError` 保存完整 partial result；通过 gate 的 checkpoint 在 resume 时直接加载、重新归一化和复验 S6，避免重跑蜂群。
6. **陈旧 S6 failure flag 污染 Audit**：加载 checkpoint 后重新执行质量检查并清除陈旧失败标记，Audit 由 limited 刷新为 approved。
7. **概述门误报**：因果连接词只统计分句起点，不再把“面向规模生产”“可利用窗口”误报为重复节点。
8. **确定性回退对象过长或型号前置**：Switchblade 公开型号投影为中文单装备主体；概述保持 120–360 字。
9. **多构型装备族凑数**：新增固定构型阻断规则，搜索型/确认型/突击型或搜索型/诱饵型/突击型不能再合并为单一画像。
10. **岸基反舰发射车语病与错分类**：去除主装备前重复“以”，补全“从……节点转变为……”的直接效果句，并把岸基反舰发射车从低空无人补射族中独立识别。
11. **Dynamic 审计语义矛盾**：独立动态 Agent + 专家 Judge 会话被视为该执行模式的 inner/middle loop 等价记录，`approved` 与 `release_ready` 保持一致。

1. 对强调装备组合质量、创新边界、专家淘汰解释和决策价值的正式研究，优先使用 `winning_swarm_dynamic_v2`。

Dynamic 完整核心路径仍明显更重：12 个主 Agent、三轮 Judge、并行 repair 与复判带来更高核心成本。完成态恢复已证明可以复用基线 Agent、18 个候选和专家账本，仅重新执行确定性 S6 复验与 Reporter；因此下一步应继续缓存专家账本、只修残差，并对项目画像章按装备组分片，而不是退回两轮或降低装备族门槛。

### 9.3 报告质量门卡点与修复

Dynamic 初次 Reporter 质量得分为 0.9375，唯一失败项是 `long_sentence_reuse_bounded`：重复长句实例占比 8.90%，四条装备风险边界各出现三次。根因是确定性验证矩阵把同一卡片的完整边界同时写入“耦合风险”和“失败条件”，再与体系贡献段叠加。

修复没有放宽 8% / 最大两次硬门：首次保留完整边界，第二处保留完整工程耦合，第三处改为“装备名 + 上述适用/反适应边界被触发 + 任务基线未达”的决策引用；随后把矩阵中的作战机理投影为“起始条件—任务动作—闭环结果”验证口径，避免与体系贡献段逐字复写。最终 Quality / Dynamic 重复长句实例占比分别为 1.66% / 5.58%，最大复用均为 2，报告门均为 1.0。

新增 H2 级密度硬门后，任何包含至少 2 个正文单元的二级章节必须达到决策密集段不少于 50%、generic filler 不高于 25%；总体决策密度仍须不少于 55%。Quality 的需求分析、项目画像、总体方案、研制基础分别为 100%、89.36%、100%、56.25%；Dynamic 分别为 100%、92.06%、100%、66.67%，两组均无低密度二级章节，整体密度分别为 88.99% 和 90.91%。

装备语义对齐硬门同时阻断四类串卡：无人艇不得写成纵深巡航效应器，共同弹体不得写成反辐射猎杀卡，反舰巡航弹不得继承反辐射关机窗口，反舰巡飞猎歼弹药不得以诱饵/电子压制作为主流程。反舰巡航弹内部又按“有限区搜索”和“协同去重”要求各自专属的流程、指标和战果标记；不能满足时不允许通过 S6。

完成态恢复还暴露了一个效率缺口：原配置指纹只覆盖 YAML 和运行参数，Reporter 交付合同代码变化不会触发 finalize 重跑。现加入显式 `REPORT_DELIVERY_CONTRACT_VERSION`；使用 `--allow-resume-config-mismatch` 时只重开 `finalize:winning-report`，复用基线 Agent、18 个候选和三轮 Judge。checkpoint 实测未重跑前置蜂群，直接进入 Reporter。

### 10.2 Reporter 去重与分章载荷

原 Reporter 将每张 1,600–1,800 字完整画像发送给所有四个分章，并要求项目画像章重新改写；交付稳定器随后又确定性注入同一画像，形成重复推理、重复输出和长尾。最终合同做了两层治理：

1. Quality / Dynamic 的 Reporter handoff 不再携带 `capability_portrait` 全文，只保留方向、装备、场景、差距、原理、流程、效果、指标、耦合、边界和发展路径等结构化线索；交付层继续按最终装备名注入完整五分点画像。
2. 四个分章只接收本章需要的字段。需求章不接收作战流程、指标和耦合字段；总体方案不接收无关效能字段；技术与研制基础章不接收完整作战流程；项目画像章保留全部结构化画像线索。

优化后 Dynamic 项目画像章从 273.913 秒降到 137.393–192.852 秒，近期三次中位数约 141.052 秒，降低约 48.5%；需求章曾从 262.117 秒降到 141.478 秒，单次 Reporter-only 墙钟达到 173.68 秒，较 274.52 秒降低 36.7%。Quality 项目画像章近期三次为 217.267 / 137.218 / 155.261 秒，中位数 155.261 秒，较原 176.277 秒降低约 11.9%。

模型侧尾延迟仍有波动：最终刷新轮 Quality 的需求章为 300.946 秒，Dynamic 为 258.624 秒；这两轮报告仍全部通过质量门。由此确认当前剩余速度卡点已从“完整画像重复改写”转移为 xhigh Reporter 的需求章偶发长尾，而不是输入过长、排队、蜂群重跑或画像注入。后续若继续优化，应采用 Reporter 请求级长尾治理或服务侧延迟观测，不应削减证据、降低推理深度、删除失败边界或重新引入报告字符硬裁剪。
