# 质量集群与动态蜂群装备质量、效率与卡点对比

## 1. 验证目标

本轮不以“Run 是否走完”作为唯一成功标准，而是检查以下交付链：

1. 前置集群/蜂群 Agent 能否先理解 Query 的任务对象、威胁、作战阶段、环境约束和制胜矛盾，再开放发散为具体武器装备；
2. 远程打击、精确打击、无人作战、新质毁伤和颠覆性成本/平台/时间关系能否在与 Query 成立时优先受到审查，但不被固定目录或关键词配额框死；
3. 最终入选项是否为可独立立项、改装、研制和试验的具体前瞻武器装备，而非能力、体系、网络、载荷包或支撑系统；
4. S6 是否保持“概述+装备与技术实现+关键作战流程+形成能力与作战效果+制胜逻辑机理与对抗边界”模板，但每张卡依据其主装备、发射/释放域、敌方目标、效应触发和结束状态重新构建真实军事场景；
5. 报告是否完整呈现逐装备能力画像、入选/参考装备区分、证据边界、反适应、失效边界和可证伪验证。

## 3. 基线结果

### 3.1 质量集群

- 状态：`failed`，S6硬门拦截支撑/恢复类内容冒充最终武器装备。
- 首轮弹性候选严重同族化：8项主要收敛为4个高功率微波车变体和4个可回收反无人拦截器变体。
- 旧 Worker 内存配置将 `finalist_maximum` 限为4，并关闭独立专家裁决；4个同分候选仅因容量被截断。
- S6并行卡片实际已形成微波效应车、高能激光效应车、可回收反无人拦截器巢车和可编程近炸弹自动炮塔车4个较具体方向，但结束前的确定性组合投影覆盖了 S6 成稿，并导致支撑方向误判。

### 3.2 动态蜂群

- 状态：`completed`，但 `report_quality_gate.passed=false`、`architecture-acceptance.release_ready=false`，说明“执行终态”不等于“高质量可发布”。
- 用时：2990.41秒（约49.84分钟）；模型调用30次；模型调用时间合计6111.314秒；最大单次调用398.47秒；最大排队315.336秒。
- 最终7项中，“百吨级远海无人水面反潜截击艇”和“大排水量潜伏猎歼无人潜航艇”较具体；其余存在：
  - 两项反UUV微型/小型鱼雷实质重复；
  - 三项以“内置/数枚鱼雷、弹药或声学标记器”的载荷枚举代替单一主装备；
  - 第2—5项被写入“敌水面编队+分层防空”的反舰场景，与水下警戒/反潜 Query 错位；
  - 多张卡的作战流程仍是对 Query 八个阶段的近义改写，而非装备专属流程。
- 报告门失败项：逐装备能力画像不完整、跨章节长句复用过多、Markdown残句/超长段落。

## 4. 已实施改进

### 4.1 稳定性

- Worker 启动前检查同名在线身份，拒绝覆盖已存在心跳；Worker Pool 不再重复拉起已被外部进程占用的槽位。
- 清理旧孤儿 Worker，消除同一 Run 被重复领取、状态回退与重复模型消耗。

### 4.2 前置候选质量

- 共享规则固定为 Query 先行：先形成任务对象—威胁—阶段—制胜矛盾语义图，再开放发散，禁止从公开型号或装备目录反向拼接 Query。
- 无人、低空、远程、精确打击、反辐射、诱饵和反无人只是由 Query 语义条件触发的优先观察镜头，不是固定清单或覆盖配额。
- 质量集群首波由4个角色扩为6个同波并发角色：前沿装备、弱信号、颠覆机理、直接战斗装备、Query条件触发的远程/精确主效武器、改变成本/平台/时间关系的非对称新质装备。增加调用数但不增加首波串行墙钟时间。
- 组合门正式要求直接战斗装备构成主体，同时检查装备族多样性、直接装备族多样性、画像完整性和独立专家裁决。

### 4.3 S6 能力画像

- 修复“并行 S6 单装备成稿被确定性组合草稿覆盖”问题：蜂群继续决定入选哪些武器及其唯一身份/对象证据，S6 Codex 会话决定场景、流程、能力画像、指标画像和制胜机理阐述。
- S6 卡片显式保护 `hypothesis_id`、主装备身份、装备形态、发射/释放域、主要目标、公开基线和对象级证据，防止串卡。
- 取消“概述必须同时出现面向—针对—利用—采用—通过—形成—实现七个连接词”的旧告警逻辑；模板只约束信息栏目，不约束句法。
- 保留硬门：概述必须具备战役/战斗地域与阶段、敌方目标与反制、我方运用主体、时敏交战过程和直接战场结果；组合内流程骨架高相似时要求按主装备重建。

### 4.4 动态合并效率

- S4—S6 贡献的 `hypothesis_id` 只能逐字复制不可变候选账本中的 ID；发现账本外新装备时，写入 `portfolio_review` 并触发受治理的组合补全波，避免高成本输出最后以 `unknown_hypothesis_id` 被拒。

### 4.5 报告质量门：军事场景优先

- 质量门不再把固定章节顺序、固定标题、逐字装备名投影和固定分点句法当作军事质量的替代物；这些项目保留为结构诊断，不再单独否决一份军事逻辑成立的报告。
- 仍保留武器主体硬门：最终组合必须为4—8项装备，至少4项为直接杀伤、拦截、压制或拒止武器，且直接战斗装备必须构成组合主体；保障、网络、C2、纯感知能力不得冒充主装备。
- 前置能力画像优先审查是否形成“具体装备—具体敌方目标—具体战区环境—部署/释放—分类与授权—跟踪/交战—战果确认—断链降级—补能再出动—失效边界”的对象级闭环。
- 报告的军事决策信息密度和长句复用阈值适度放宽，允许按不同装备自然组织叙事；公开证据、事实与推断边界、可证伪验证和失效条件仍是硬门。
- 公开来源绑定下限由90%降为80%。降低的是覆盖率形式要求，不是事实可信度要求；未绑定声明必须原文保留并标明推断缺口，不得隐藏或改写成已证实事实。

### 4.6 断点恢复与交付一致性

- 新增报告交付专用恢复路径。若基线 Packet、S1—S6、能力画像、专家评判和 Reporter 成稿已完成，只重跑确定性的报告规范化、来源绑定、报告质量门、交付物和审计，不再进入 Recall，也不再调用已完成 Agent。
- 恢复轨迹已验证：`baseline_agent_calls=0`、`winning_stage_calls=0`、`reporter_model_calls=0`。因此报告门参数调整或交付物修复不会重复消耗基线 Agent、S1—S6、专家判断和 Reporter。
- 报告生成后重新构建一次交付物，保证渲染、门控、内存对象和磁盘文件使用同一报告版本；失败时同步写入当轮 `branch_deliverables.json` 和 `report_failure.json`，不再出现内存判失败但磁盘仍显示旧版本完成的状态分裂。
- 恢复写入使用内容版本化的 Proposal ID/幂等键，避免更新审计、报告或能力卡时触发历史 `proposal_id conflict`。

## 5. 复测验收标准

- 运行稳定：无重复 Worker、无同 Run 重复领取、无状态回退、无孤儿 Codex 会话。
- 效率：记录墙钟时间、模型调用数、模型时间合计、最大排队、动态角色数、波次、拒绝/修复/补全次数。
- 候选装备：标题为单一具体主装备，相对最近公开基线有可识别的构型/导引/突防/毁伤/授权/成本关系增量，同族变体不得靠改名占位。
- S6：每张卡主装备唯一，场景与 Query 一致，流程主语/发射域/目标/授权/毁伤/再组织全程一致，制胜机理说明改变对手的时间、成本、暴露或资源分配关系。
- 报告：`report_quality_gate.passed=true`；优先检查真实军事场景、武器主体、作战链闭合、证据与推断边界，不再要求所有装备使用相同标题、相同句法或相同分点数量。
- 恢复：完成过的基线 Agent、S1—S6、专家判断和 Reporter 不重复调用；交付物内存状态与磁盘状态一致。

1. 短停式车载高功率微波削峰车；

4. 被动交接定向电子攻击压制车。

四项均为可以独立研制、改装和试验的具体反无人作战装备，覆盖电子压制、微波面杀伤、激光/炮弹清漏和空中截击，不再被“微波车改名占位”主导。场景集中在近海营旅伴随防护、低空多轴蜂群突入、弱网本地交战、友邻无人机混飞和连续波次再装填，装备形态、效应方式、交战窗口与失效边界区分清楚。

1. “断前哨”低成本反UUV自主拦截鱼雷；
2. “驼鲸”水下无人母艇—效应器再投送艇；

## 7. 军事场景与画像质量判断

### 7.1 已达到的质量

- 两条 Query 的主装备均聚焦具体前瞻武器形态，不再以“无人体系”“智能网络”“多域协同能力”等抽象名词替代装备。
- 能力画像能围绕相应装备聚集真实军事制胜场景：明确敌方潜艇、UUV、诱饵或蜂群的行动方式，明确我方使用主体、发射/释放域、授权边界、直接效应、战果确认和再组织条件。
- 动态蜂群报告不再把同一八阶段模板机械改写给所有卡片。武装USV突出拖曳阵海况边界和主动开源风险，XLUUV突出前置隐蔽部署与接触保管，拦截器突出限域授权、友方排除和低成本交换比，场景与指标已有对象级差异。
- 质量门最终诊断中，模板结构、装备主体、内容闭环、证据与验证边界、军事决策信息密度均通过。固定标题和装备名未逐字一致仅作为诊断，不再压过军事内容判断。

### 7.2 仍需继续改进

- 动态蜂群报告仍有“形成形成”“以以”等局部机械拼接，以及个别概述过长；这类问题没有破坏军事逻辑，但应在 Reporter 后处理增加重复词和超长概述清理。
- “接触保管”XLUUV画像仍出现“采用2至5个专属测量轴”但未逐项完全展开，说明画像门对“宣称存在指标轴”和“真正写出指标轴”区分仍不够严格。
- 小型水下自主拦截弹与“浅刺”反UUV鱼雷存在同族重叠。后续组合门应要求两者在母平台、封装方式、射程/留置方式、目标级别、毁伤机理和补装模式上至少形成两个不可替代差异，否则只保留一项、另一项转参考。
- 动态蜂群能力记录与最终报告之间存在战场化重命名和7项到6项的编辑收敛。该做法可以接受，但交付物应显式记录“原始候选—入选装备—参考/依赖—报告名称”的映射，避免用户误以为候选被无依据删除或替换。

## 8. 动态蜂群主要效率卡点

1. **组合置信度空值假失败**：部分已通过专家门的组合因聚合置信度字段为空被当作零分，触发不必要修复；现已允许权威专家裁决和S6通过结果覆盖历史L1—L3词法诊断。
2. **局部修复截断完整组合**：早期3卡局部修复返回后覆盖原有完整组合，导致已合格卡片丢失；修复后局部结果只替换对应卡片，不再重建整个组合。
3. **恢复重复消费**：旧恢复路径会重复进入S6、Recall和基线 Agent。报告专用恢复现复用已完成产物，实测三类模型调用均为0。
4. **批量修复长尾**：一次批量修复运行864.699秒后仍失败；改为逐卡并行后约277秒完成一轮，相比批量路径缩短约68%。另一次单卡复修为198.338秒，说明单张高复杂度水下装备画像仍可能形成长尾。
5. **Proposal ID 冲突**：恢复时对同一审计、报告或能力卡使用对象级固定键，内容变化后发生冲突；现改为内容版本化键。
6. **交付物状态分裂**：质量门失败时，内存已失败但磁盘 `branch_deliverables.json` 仍可能保留历史完成状态；现已同步覆盖，并在通过后删除当轮 `report_failure.json`。
7. **公开来源形式门过紧**：90%绑定率会因少数透明标注的推断项阻塞一份军事内容成立的报告；改为80%后，本次以21/26通过，同时完整保留5条未绑定声明供审查。

## 9. 结论

- **质量集群更快、更稳、更聚焦**。在任务边界清楚、装备领域相对已知时，适合用较少调用快速收敛为高质量、具体且可试验的武器组合；本轮313.622秒、12次模型调用完成，报告质量得分1.0。
- **动态蜂群发散与专家选择能力更强**。它能生成水下母艇、坐底拒止武器、武装USV和多类反UUV效应器等更宽的组合空间，但组合一致性、同族去重、S6长尾和恢复治理成本明显更高。
- **报告质量门应围绕战争问题，而不是围绕排版模板**。核心判断应是：是否为具体新质武器装备，是否直接作用于真实敌方目标，是否在具体战区和交战链上产生可解释战果，是否说明授权、反适应、失效和验证边界。固定标题、固定句法和逐字名称匹配只能作为诊断，不能代替军事专家判断。
- **公开来源绑定率可以低于90%，但不能降低军事内容和证据诚实性**。80%是本轮可接受下限；任何未绑定关键结论仍必须显式标注为推断或待验证，不得用高绑定率掩盖错误场景、抽象装备或机械画像。
- **断点恢复已转为增量恢复**。报告交付问题不再重复消耗基线 Agent、S1—S6、专家判断和 Reporter，恢复成本集中在确定性门控和落盘一致性处理。
