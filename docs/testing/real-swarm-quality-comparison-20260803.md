# `swarm_quality_v1` 与 `winning_swarm_dynamic_v2` Real 对比、修复与复验

日期：2026-08-03  
Query：`强电磁压制下精确打击任务续接装备研究`  
共同配置：real / Codex / `gpt-5.5` / 自动路线 / 自动分支 / 专家交互 / 2 轮 / `project_argument_v1`

本轮使用同一 Query 分别实跑两个模式，重点检查能力画像的装备落点、作战流程、制胜机理、验证边界，以及研究报告的深度、结构完整性、内部标记泄漏和执行长尾。原始运行、`report.md`、数据库、trace 和 Reporter 会话全部保留；历史报告修复只新增 postfix 产物。

### 主要速度卡点

- 质量模式最长调用为 S6 能力画像综合，570.646 秒；同时发生 2 次 inner retry、9 次 inner review，S2 最长排队 94.651 秒。
- 动态模式最长调用为 Reporter 能力画像，475.039 秒；需求分析 393.766 秒、技术基础 382.111 秒，报告长章仍是关键路径。
- 两组累计模型耗时均显著高于墙钟，说明并行确实生效；进一步优化应针对长尾任务拆分、首次成稿稳定性和重复复核，而不是削减证据或恢复篇幅硬门禁。

## 2. 能力画像质量

### 2.1 `swarm_quality_v1`

最终形成 5 项具体、互异的装备方向：

1. JASSM-ER 空射巡航导弹抗扰突防升级。
2. PrSM 地射导弹机动目标毁伤升级。
3. Harop 失辐射等待反辐射巡飞弹。
4. Barracuda-500M 低成本巡航效应器。
5. MALD-J 空射电子攻击压制效应器。

优势是型号锚点清楚、装备族组合稳定、多样性较好，公开基线与拟议工程增量容易区分。主要不足是 S6 汇总长尾明显，部分画像的创新逻辑更依赖确定性投影补齐，动态批判密度低于动态蜂群。

### 2.2 `winning_swarm_dynamic_v2`

页面最终形成 5 项装备方向：

1. 固定构型长航时巡飞猎歼弹药。
2. 关机目标再捕获反辐射弹药。
3. 远程精确制导弹药。
4. 箱式发射低空可消耗察打一体无人机。
5. 分布式巡飞弹药续接首击后目标再确认与补射。

动态画像在以下方面更强：

- “关键作战流程”能够明确任务装订、目标复核、交战处置、持续续接及拒打/降级门槛。
- “形成能力与作战效果”使用轨迹保持率、重新授权时延、正确拒打率、再捕获与补射时间等差异化指标，而不是通用覆盖/响应模板。
- “制胜逻辑机理与对抗边界”能把装备独有工程增量、任务时序和对手反制放在同一条因果链中。
- “发展与验证路径”保留弱网、PNT 受扰、诱饵、关机机动、接口版本差异等可证伪场景及转段门槛。
- 每项验证路径固定按“环境—对照—决策”闭合，分别交代代表性对抗条件、与未改装或串行任务链的比较指标，以及停止转段、拒打、降级或重新校准条件。

历史运行中仍存在两个高度相近的巡飞/低空补射方向，说明原始候选组合对同族重复识别不足。当前代码已把 Harop/巡飞猎歼与普通巡飞弹统一归入广义 `loitering_munition` 装备族，后续新运行不会再将它们虚算为两个互异装备族。

### 2.3 展示结构修复

能力画像卡片已合并为六个互补模块，去除了“武器装备发展落点、核心作战机理、型号发展与演化路径、核心差距、预期任务效果”等重复区块：

1. 概述。
2. 装备与技术实现。
3. 关键作战流程。
4. 形成能力与作战效果。
5. 制胜逻辑机理与对抗边界。
6. 发展与验证路径。

“约 800 字”按六个模块分别作为可按需展开的深度目标理解，整张画像不设置 800 字或其他字符硬上限，也不再通过截断、回切完整句或合并成单段进行破坏性压缩。通过质量门的长 S6 模型原文会被 API、Runner 和报告投影原样保留；六个模块之间显式分段，便于逐项评审。

同时修复了候选 `A.`–`H.` 前缀、AARGM-ER 误命名、内部论证句混入、作战流程不足四步、验证指标同质化、弱网约束在压缩中丢失，以及动态事件显示为“SNone 专用 Agent”等问题。

页面复核进一步发现装备族锚点会被比较性文本污染：Harop 画像因“不与 MALD 复合”被误识别为电子攻击，Barracuda 因“地面发射接口”被误识别为 PrSM，部分以 Harop 为公开基线的低空补射画像又被误识别为反辐射装备。现已改为主装备形态优先、任务增量次优先、比较性提及最后判断，并为证据缓存、反辐射、低成本巡航效应器、电子攻击、低空无人补射、PrSM 和 JASSM 分别设置流程、指标与验证合同。两份 postfix 已据此重新生成。

## 3. 研究报告质量与泄漏根因

两组原始报告均完成五章深度报告，没有模型失败、fallback 或“限时保底报告”。需求分析已从模板描述扩展为任务链断点、时间链、信息链、火力链、保障链、装备族方案和失效边界的实质论证。

但原始报告出现严重内部标记泄漏：

| 扫描项 | 质量模式原报告 | 动态模式原报告 |
|---|---:|---:|
| `〔改写断点：保留事实但不得照录〕` | 12 | 42 |
| `A.` 候选前缀 | 0 | 3 |

根因不是 Reporter 最终清理失效，而是清理后的正文又被确定性投影覆盖：带内部标记的 Reporter handoff 被重新写入技术矩阵、能力表格和研制基础，导致标记在最终交付阶段回流。

## 4. 已实施修复

### 4.1 三层报告封堵

1. handoff 层不再插入改写断点，并清除 `A.`–`H.` 候选前缀。
2. 确定性投影层统一清理内部标记，`synthesis_seed` 为空时回退到 `research_handoff`，稳定器返回前再次清理。
3. Reporter 草稿门与正式质量门将改写断点、候选前缀设为阻断项；Runner 和 postfix 在最终正文清理后重新验收。

正式质量门新增：

- `has_no_internal_rewrite_boundary`
- `has_no_internal_candidate_prefix`

任一项失败都会阻止正式通过。

### 4.2 S6 高质量阻断策略

- S6 不再服从运行 wall-clock deadline、临近截止降级窗口或全局模型调用预算，不设置短 provider timeout。
- 每次生成使用 `xhigh` 推理，并允许最多 3 次完整重生成或定向修复；可通过 `EQUIPMENT_DR_S6_MAX_QUALITY_ATTEMPTS` 在 2–4 次之间调整。
- 传输层仍保留两次正常重试，但模型不可用或传输最终失败时直接失败，不再拼装本地“限时保底画像”。
- 系统性缺陷触发完整 S6 重生成，局部卡片缺陷才使用定向修复；最终质量门仍不通过时抛出 `S6QualityError`，阻断报告交付。
- 动态调度器会传播异步 S6 异常并取消其他未完成任务，避免后台任务失控或错误被吞掉。

### 4.3 历史报告的非破坏复算

### 4.4 评审页读取链路

此前“报告评审”和 Benchmark 固定读取原始 `report.md`，导致磁盘上已有合格 postfix 时页面仍展示旧泄漏内容。现已改为：只有 `report-quality-gate-postfix.json` 明确 `passed: true` 时优先读取 `report-postfix.md`；postfix 不存在、质量门失败或 JSON 损坏时安全回退到原始 `report.md`。这一变更不覆盖原始文件，兼顾评审可用性与审计留痕。

## 6. 结论

1. 本轮 `winning_swarm_dynamic_v2` 反而更快，主要因为质量模式出现 S6 570 秒长尾、重复内审和排队；仍需多 Query 样本才能判断稳定速度排序。
2. `swarm_quality_v1` 的装备组合更稳定、型号多样性更好，适合作为可重复交付基线。
3. `winning_swarm_dynamic_v2` 的流程细节、制胜机理、反制边界和验证可证伪性更强，但历史样本暴露同族重复风险，现已在装备族分类层修复。
4. 两份 postfix 报告均在新增的严格逐画像质量门下以 1.0 通过；每份均有 5 个画像、30 个受控模块、5 组“环境—对照—决策”验证链，内部改写标记、候选前缀、省略号、列表序列化残片和内部引用均为 0。
5. 未恢复任何 12,000 字符硬门禁；质量优化依靠结构、交接、质量门和长尾治理，而不是破坏性压缩。
6. S6 已取消限时保底与临近截止降级；以后只有通过高质量门的 S6 画像才允许进入交付链，失败会明确阻断而非静默降级。
