## 配置语义

`tools`、`knowledges`、`mcps`、`skills` 的 `null` 表示当前身份有权使用的全部资源，`[]` 表示不选择资源。权限始终由后端解析。子智能体沿用既有规则：空选择表示当前身份可见的全部子智能体；关闭 `subagents_enabled` 才是禁用子智能体。

`preload_skills` 必须属于已选 Skill。激活根 Skill 时会展开其传递依赖，循环依赖稳定去重。未授权 MCP 会从 Skill 运行快照中移除，不能通过安装 Skill 扩大外部能力权限。

`mcp_tool_loading` 支持 `on_demand`（默认）和 `eager`。按需模式把服务摘要放入系统索引，初始不加载全部远程工具 Schema；模型激活服务后获取并调用其工具。会话恢复时只恢复当前运行仍有权使用的服务。服务不可用时返回明确的工具错误，其他能力仍可继续运行。

内置 Skill 的内容和依赖仍由代码管理；管理员可以限制使用角色或停用。内容同步会保留已保存的角色限制。个人 Skill 保持用户隔离，不提供跨用户共享。

远程安装继续使用独立沙盒，不继承用户运行凭据。来源白名单默认包含 `github.com`、`skills.sh`、`modelscope.cn`。skills.sh 链接解析到 GitHub，因此两者均须被允许；管理员已有的显式来源策略仍优先。

## 数据库与升级

本轮业务 Schema 从 13 升级到 14，仅新增可空的 `mcp_servers.access_policy JSON`。空值保持既有 MCP 的全局使用语义。标准存储迁移已包含该升级；已有 13 版本数据库也可执行独立的新增字段迁移：

```bash
docker compose exec -T api uv run --no-sync --no-dev python -m platform_core.storage_migrations.v077_mcp_access
```

独立迁移只处理 13 → 14，不迁移历史目录、不终结运行。实际 PostgreSQL 已验证重复执行幂等。更新后需重新加载 API、Worker 与前端。
